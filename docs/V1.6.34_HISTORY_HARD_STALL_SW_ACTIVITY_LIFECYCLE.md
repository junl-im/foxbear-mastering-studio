# v1.6.34 History Hard-Stall and Service-Worker Activity Lifecycle

## Audit scope

- Overlay History API transactions, delayed and omitted popstate, BFCache, repeated Back protection.
- Service-worker update coordination, cross-tab heartbeat, BroadcastChannel, localStorage fallback and repeated registration.
- Audio engine, Worker, AudioContext, Object URL, download and PWA lifecycle regression gates.

## Problems found

1. After the initial 1.5-second overlay history watchdog, an unchanged sentinel was marked as a hard stall but remained in-flight forever if the browser never traversed. Later dialogs could not install a fresh sentinel.
2. The service-worker activity coordinator kept its heartbeat/channel lifecycle implicit across BFCache and added an anonymous `updatefound` listener on every `coordinate()` call. Repeated registration could accumulate listeners, while BFCache restoration had no explicit immediate re-advertisement contract.

## Changes

- A terminal 30-second watchdog neutralizes an unchanged stale sentinel in-place without issuing another Back.
- If a dialog reopened during the stall, the existing sentinel is retained and becomes the active user-Back guard.
- BFCache pagehide pauses the heartbeat, closes BroadcastChannel and removes the local activity record; pageshow reopens and immediately publishes activity.
- Registration observers are installed once per ServiceWorkerRegistration while their latest coordination options remain updateable.
- Performance diagnostics expose terminal recovery and service-worker activity lifecycle counters without URLs or user content.
