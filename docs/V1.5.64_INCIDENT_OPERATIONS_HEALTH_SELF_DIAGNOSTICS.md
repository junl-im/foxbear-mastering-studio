# v1.5.64 Incident Operations Health Self-Diagnostics

## 목적

v1.5.63까지의 메일 큐 복구는 신고가 존재할 때 발송 경로를 복구했지만, Gmail 앱 비밀번호가 잘못되거나 계정 인증이 차단된 경우에는 실제 신고가 발생하기 전까지 이상을 발견하기 어려웠습니다. 또한 장기 미발송, 최종 실패 누적, 일일 요약 실패와 예약 카운터 정체가 관리자 화면에서 하나의 운영 상태로 정리되지 않았습니다.

v1.5.64는 15분 주기의 서버 자가진단을 추가해 문제 보고 메일 시스템 자체를 감시합니다.

## 진행된 개선

- `auditIncidentMailOperations` 예약 함수를 15분마다 실행합니다.
- SMTP/Secret 상태는 Nodemailer `verify()`로 확인합니다.
  - 정상 상태에서는 최대 6시간 캐시합니다.
  - 큐 이상 또는 이전 SMTP 오류 상태에서는 30분 간격으로 다시 확인합니다.
  - Google 앱 비밀번호의 명시적 만료 시각은 API에서 제공되지 않으므로, 실제 인증 성공 여부와 16자리 Secret 형식으로 만료·폐기·차단에 준하는 이상을 감지합니다.
- 아래 상태를 `incidentOperations/mail`에 저장합니다.
  - `healthy`, `warning`, `critical`
  - 대기·실패·발송 중·재시도·최종 실패·완료 건수
  - 장기 미발송 건수
  - KST 일일 발송/예약 수와 예약 누수 후보
  - 최근 3일 요약 실패·잠금 정체
  - SMTP/Secret 점검 결과와 점검 시각
  - 최근 정상 신고 메일 발송 시각
- 장기 미발송은 다음 기준으로 감지합니다.
  - `pending`: 생성 후 10분 초과
  - `failed`: 재시도 예정 시각을 5분 초과
  - `sending/retrying`: 임대 만료 후 5분 초과
  - 구형 `suppressed-rate-limit`: 자동 복구가 필요한 장기 미발송으로 계산
- 최종 실패 1건 이상은 주의, 5건 이상은 위험으로 분류합니다.
- 장기 미발송 1~2건은 주의, 3건 이상은 위험으로 분류합니다.
- 최근 요약 실패 2건 이상 또는 요약 임대 정체는 위험으로 분류합니다.
- SMTP가 정상일 때 운영 상태가 바뀌면 경보 메일을 보내고, 같은 문제가 지속되면 12시간 쿨다운 후 다시 알립니다.
- 위험/주의 상태에서 정상으로 돌아오면 복구 메일을 보냅니다.
- SMTP 자체가 실패한 경우 같은 SMTP로 경보를 보낼 수 없으므로 Firestore 관리자 화면에 위험 상태를 남기고, 인증이 복구된 이후 복구 경보를 보냅니다.
- 운영 점검 작업은 임대 ID로 중복 실행과 늦은 완료를 차단합니다.
- 관리자 오류 화면에 운영 상태, 장기 미발송, 최종 실패, SMTP/Secret, KST 발송 한도를 표시합니다.
- 관리자 화면의 오늘 오류 수는 브라우저/UTC 문자열 비교가 아니라 KST 날짜 범위 서버 집계로 변경했습니다.

## Firestore 및 배포

- 관리자만 `incidentOperations/mail` 문서를 읽을 수 있습니다.
- 클라이언트 쓰기와 목록 조회는 허용하지 않습니다.
- 최근 정상 발송 시각 조회를 위해 `delivery.status + delivery.checkedAt DESC` 복합 인덱스를 추가했습니다.
- 배포 대상에 `functions:auditIncidentMailOperations`가 추가됩니다.

```bash
firebase deploy --only firestore:rules,firestore:indexes,functions:sendIncidentEmail,functions:retryFailedIncidentEmails,functions:retryIncidentEmailRequest,functions:sendDailyIncidentSummary,functions:auditIncidentMailOperations
```

## 제한 사항

- Gmail/Google은 앱 비밀번호의 미래 만료 시각을 제공하지 않습니다. 본 패치는 Secret 형식, SMTP 인증, 연결, 수신자 승인 결과로 실제 사용 가능 상태를 판단합니다.
- SMTP 장애 중에는 동일 SMTP 채널로 경보 메일을 보낼 수 없습니다. 이 경우 관리자 화면과 Firestore 운영 문서가 1차 경보 채널입니다.
- 실제 Gmail 수신과 Firebase 예약 실행은 Firebase 프로젝트 배포 권한과 Secret이 있는 환경에서 최종 확인해야 합니다.
