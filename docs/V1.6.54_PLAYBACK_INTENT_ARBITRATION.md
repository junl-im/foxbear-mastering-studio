# v1.6.54 Playback Intent Arbitration

## Audit findings

A browser does not always update `HTMLMediaElement.paused` immediately when `play()` is requested. On mobile, KakaoTalk WebView, or a source that is still preparing, the promise can remain pending while `paused` still reports `true`.

That created three edge cases:

1. A rapid second tap could be interpreted as another Play instead of Pause.
2. A late completion from the first Play request could restart audio after the user had already requested Pause.
3. Exclusive playback only paused elements that were already audibly playing, so another preview with a pending Play request could become audible later.

Background transport capture and Media Session pause also relied primarily on the current `paused` property, which could lose the user's newest request while playback was settling.

## Patch

### Explicit playback intent

- Each audio element records the newest requested playing state separately from the browser's delayed media state.
- Play, Pause, crossfade-in, crossfade-out, synchronized playback, cancellation, and exclusive orchestration update that intent.
- Toggle controls use the requested state, so a second rapid tap correctly becomes Pause even before the first `play()` promise settles.

### Stale request settlement

- A Play request that no longer owns the current generation reports `false`.
- When the newest intent is Pause, a late Play completion is immediately stopped and its audible target volume is restored.
- Settlement avoids redundant `pause()` calls when the element is already stopped.
- A newer Play intent is never paused by an older request that finishes late.

### Exclusive and lifecycle continuity

- Starting another preview cancels pending competing Play requests through the transition service.
- Difference-listen and Dock cleanup use the same request-cancellation path.
- Background transport capture stores the latest requested state rather than only the instantaneous `paused` value.
- Media Session Pause routes through intent-aware fade/cancellation logic, with a safe direct-pause fallback for isolated environments.

## Regression coverage

`qa/v1654_playback_intent_arbitration_smoke.js` verifies:

- Play intent is observable before the native Play promise settles;
- rapid Play then Pause leaves the element stopped after late completion;
- rapid Play, Pause, Play preserves the final Play request;
- exclusive playback cancels a competing pending start;
- Dock, background transport, Media Session, and legacy-exclusive paths use intent-aware contracts.

Historical transition, preview ownership, mobile return, post-master readiness, and crossfade settlement regressions remain enabled.
