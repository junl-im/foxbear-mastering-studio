# v1.5.90 Browser Retry Integrity and Metadata-Aware Scope Audit

## Audit findings

1. A failed Playwright case could be skipped during `--last-failed` retry and still be counted as recovered because skipped results were treated as passing.
2. The retry reporting step was informational only, so a successful Playwright process with incomplete retry evidence could allow deployment.
3. Generated release metadata touched core files such as `package.json`, `index.html`, `sw.js`, and runtime version constants, which could unnecessarily promote every release to the complete Browser suite.
4. Flaky-history entries had no age-based expiry and could remain permanent warnings after the underlying issue disappeared.
5. Custom Markdown and issue-report paths did not consistently create their own parent directories, and custom tests could write a default issue artifact into the repository.

## Applied recovery

- Real retry passes are separated from skipped, repeated, and missing outcomes.
- `qa/browser/verify-retry-recovery.js` validates that recovered count equals primary failure count and rejects all incomplete outcomes.
- Both GitHub Pages workflows run the verifier after retry reporting.
- Release metadata at the base and head Git revisions is normalized before change-impact classification. Functional text remains visible after normalization and therefore still triggers selected or full Browser QA.
- Flaky history defaults to a 45-day retention window and tracks skipped retry outcomes explicitly.
- All custom report output directories are created independently.

## Verification

- Synthetic primary failure plus skipped retry is rejected by the summary and CLI verifier.
- Synthetic complete retry passes verification.
- Temporary Git history confirms package, index, and runtime version-only changes are classified as metadata-only.
- A functional runtime edit remains non-metadata and browser-impacting.
- Stale flaky entries are removed after the retention window.
- Both deployment workflows contain reporting followed by fail-closed retry verification.
