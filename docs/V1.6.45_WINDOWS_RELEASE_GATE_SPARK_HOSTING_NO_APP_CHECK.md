# v1.6.45 Windows Release Gate, Spark Hosting Hygiene, and No-App-Check Policy

## 문제

- 최신 Windows/Node 환경에서 `spawnSync('npm.cmd')`가 `EINVAL`로 실패해 릴리스 검사가 시작되지 않았다.
- 저장소 루트에 유입된 `cmd.exe`가 Firebase Hosting `public: "."` 대상에 포함되어 Spark 요금제 배포가 중단됐다.
- 운영 정책은 App Check를 사용하지 않기로 결정했지만, 클라이언트·CSP·관리자 진단에는 App Check 설정 안내가 남아 있었다.

## 수정

- 릴리스 게이트가 `.cmd` 파일을 직접 실행하지 않고 현재 Node 실행 파일로 npm CLI JavaScript 엔트리를 실행한다.
- Firebase Hosting ignore, Git ignore, 릴리스 ZIP 생성기, 덮어쓰기 ZIP 생성기, ZIP 검증기에 Windows 실행 파일 확장자 차단을 추가한다.
- `deploy:spark`와 Hosting을 포함하는 `deploy:incident` 앞에 Hosting payload 사전 검사를 실행한다.
- App Check SDK 동적 import, reCAPTCHA 사이트 키, App Check 토큰 헤더, 관련 CSP/Trusted Types 허용 범위를 제거한다.
- 기존 진단 데이터 형식은 `mode: disabled`로 유지하고 관리자 화면에는 `미사용 정책`으로 표시한다.
- 관리자 권한은 Firebase Google Authentication과 Firestore `siteAdmins/{UID}` Rules만으로 검증한다.

## 운영 적용

1. 기존 작업 폴더의 `cmd.exe`는 삭제한다.
2. 덮어쓰기 ZIP을 저장소 루트에 적용한다.
3. `npm run check:release`를 실행한다.
4. `npm run deploy:spark`를 실행한다.
5. Firebase Console의 App Check Enforcement는 Firestore와 Authentication 관련 리소스에서 활성화하지 않는다.

## 검증 계약

- Windows 호환 npm CLI 실행 경로가 존재하고 `npm.cmd` 직접 spawn이 없어야 한다.
- Hosting ignore에 실행 파일 차단 패턴이 모두 존재해야 한다.
- 릴리스/덮어쓰기 ZIP에 실행 파일이 들어가면 검증이 실패해야 한다.
- App Check SDK·사이트 키·토큰 헤더·reCAPTCHA CSP 허용이 런타임에서 없어야 한다.
- Google Auth의 정확한 gapi 로더 및 gapi 모듈 Trusted Types 허용은 그대로 유지해야 한다.
