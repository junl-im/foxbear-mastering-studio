# v1.6.89 Mobile header flex ownership browser gate recovery

## Context

GitHub Actions v1.6.88 continued to report one repeated `chromium-mobile-pwa` Runtime Health failure with `rowOverlap = 91.96875px` even after the compact header's grid columns were explicitly assigned. The desktop browser case remained healthy.

## Change

- Replaces the final `<=430px` command-header ownership layer with a two-rail nowrap Flexbox contract.
- Gives `.brand-command-left` `flex: 1 1 0`, `width: 0`, and `min-width: 0` so it can only occupy remaining space.
- Gives `.brand-right-actions` `flex: 0 0 auto` plus `margin-left: auto` so workspace/settings controls own the trailing edge without sharing the left rail's box.
- Keeps the device glyphs and workspace/settings actions while retaining the existing compact text reductions.
- Keeps Runtime Health's strict `rowOverlap <= 1px` acceptance threshold.
- Throws explicit `FOXBEAR_HEADER_OVERLAP_INITIAL` / `FOXBEAR_HEADER_OVERLAP_320` errors containing the measured geometry if the browser gate ever regresses again.
- Keeps `PATCH_MANIFEST.json` auto-removal but suppresses only that known legacy path's repetitive GitHub warning annotation; other repaired generated paths still emit warnings.

## Safety

The desktop command header remains on the established grid contract. The Flexbox override is limited to Pixel-class widths (`<=430px`) and does not weaken the browser assertion or remove essential controls.
