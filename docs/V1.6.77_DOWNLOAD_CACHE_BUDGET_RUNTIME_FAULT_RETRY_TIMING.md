# v1.6.77 Download Cache Budget, Runtime Fault Precision, Retry Timing

## Summary

- Bounded converted-download variant cache across all completed tracks.
- Low-memory/mobile policy: 64 MiB and at most 2 converted variants.
- Standard policy: 192 MiB and at most 5 converted variants.
- WeakRef-backed LRU registry avoids keeping completed source blobs alive only for cache accounting.
- Track release/output invalidation explicitly clears converted variants.
- Runtime fault diagnostics distinguish one repeating fault from several unrelated one-off recoveries.
- Incident admission retry guidance points to the real minute/hour/KST-day bucket boundary.
- Download dialog resynchronizes visual viewport geometry after mobile rotation and page restoration.

## Safety contract

The converted download cache is optional. If WeakRef is unavailable, FoxBear skips converted-variant caching rather than accepting an unbounded memory-retention risk. A cache eviction never removes the canonical mastered `outBlob`; it only discards a derived format that can be generated again.
