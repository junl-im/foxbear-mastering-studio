# v1.6.46 Google Auth same-origin network recovery

## Incident

Administrator authentication reached Firebase Auth but failed before Google account selection with `auth/network-request-failed`. The failure happened before any `siteAdmins/{UID}` lookup, so changing the administrator document could not recover it.

The production page is normally opened on `foxbear-music.web.app`, while the previous Firebase configuration always used `foxbear-music.firebaseapp.com` as `authDomain`. Firebase documents that a `web.app` Hosting subdomain should use the domain serving the app as `authDomain` when redirect authentication is required, so the app and authentication helper use the same origin.

## Recovery

- Resolve `authDomain` to the current approved Firebase Hosting hostname:
  - `foxbear-music.web.app`
  - `foxbear-music.firebaseapp.com`
- Keep `foxbear-music.firebaseapp.com` as the fallback for local and non-Hosting development.
- Permit the two project Hosting origins in synchronized document and Hosting CSP `frame-src` and `connect-src` directives.
- Retry popup-blocked, unsupported-environment, and `auth/network-request-failed` cases once through `signInWithRedirect`.
- Fence redirect attempts in session storage to prevent a navigation loop.
- Detect a missing redirect result and retain a safe diagnostic for the next administrator dialog open.
- Expose only error code, page origin, auth domain, online state, and query-free rejected script path. OAuth parameters, query strings, tokens, and account data are not recorded.

## Required production console setting

Keep both Firebase Hosting domains in Firebase Authentication Authorized domains. In the Google OAuth 2.0 web client used by Firebase Authentication, authorize:

```text
https://foxbear-music.firebaseapp.com/__/auth/handler
https://foxbear-music.web.app/__/auth/handler
```

The trailing `/__/auth/handler` is required.
