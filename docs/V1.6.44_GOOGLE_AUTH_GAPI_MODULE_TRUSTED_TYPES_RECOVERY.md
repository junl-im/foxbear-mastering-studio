# v1.6.44 Google Auth gapi module Trusted Types recovery

## Incident

The v1.6.43 default Trusted Types policy allowed the Firebase Auth bootstrap loader at `https://apis.google.com/js/api.js`, but the loader subsequently requested a generated gapi iframe module under `https://apis.google.com/_/scs/apps-static/_/js/...`. The second-stage module was rejected by the FoxBear allowlist and administrator Google sign-in stopped with the Korean dynamic-script rejection message.

## Change

- Keep `require-trusted-types-for 'script'` enabled.
- Continue allowing the exact Firebase Auth loader `/js/api.js`.
- Add only the generated gapi module prefix `/_/scs/apps-static/_/js/` on `https://apis.google.com`.
- Keep unrelated `apis.google.com` paths, lookalike static directories, uploads, and external origins blocked.
- Record only rejected origin and pathname for diagnostics; query strings and callback values are not retained.
- Normalize the FoxBear rejection into the administrator authentication recovery message.

## Validation

- Dedicated regression: `qa/v1644_google_auth_gapi_module_trusted_types_recovery_smoke.js`.
- The regression covers the initial loader, generated iframe module, blocked lookalikes, and query-free diagnostics.
- Full static, behavioral, release, archive, engine, and golden-audio results are recorded in `qa/QA_REPORT.md` and `STATUS.md`.

## Production

Deploy with `npm run deploy:spark`, then close all existing FoxBear tabs and reopen the site. If an older service worker remains active, clear site data once before retrying Settings → 관리자 모니터링 → Google 계정으로 인증.
