# v1.6.21 Incident Lifecycle Recovery and Network Exploration

## Scope

This release centralizes incident connectivity and resume behavior and adds a bounded network-exploration phase for the two authenticated Firebase transport routes.

## Lifecycle coordinator

`src/boot/incident-lifecycle-service.js` owns online, offline, document visibility, and Network Information API change listeners. It records only coarse timing and network-class metadata and calls reporter-provided recovery hooks.

A visible return after at least five minutes is considered a long resume. The reporter then runs one deduplicated sweep that may flush the anonymous local queue, refresh active mail delivery history, verify the incident service, and refresh stale deployment readiness.

## Route exploration

A changed coarse network key decays prior route scores by 50 percent, clears stale cooldowns, and opens four actual route attempts. The preferred route alternates Callable and Hosting same-origin until the exploration budget is exhausted, after which cooldown and bounded success-rate policy resume.

`recordAttempt()` is invoked immediately before a request begins. Health reads and UI rendering never consume the exploration budget.

## Privacy

Lifecycle and route state may include online/offline state, browser-provided connection class, timestamps, counters, and limited error codes. It excludes IP address, SSID, carrier identity, location, audio, filenames, report bodies, local paths, authentication tokens, and Firebase Secrets.
