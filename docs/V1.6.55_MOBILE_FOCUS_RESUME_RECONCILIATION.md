# v1.6.55 Mobile Focus Resume Reconciliation

## Problem

Mobile browsers can pause the HTML audio element when the page backgrounds, a phone call takes focus, or the active headset/Bluetooth route changes. The application could still retain a playing intent even though the element was paused. A blocked automatic resume then left the first Dock tap interpreted as pause instead of play.

## Changes

- Added `playback-lifecycle-recovery-service.js` to coordinate visibility and page-return recovery outside the main application bundle.
- Added bounded `resumeAfterInterruption()` recovery to the transition service.
- Automatic resume failure now clears stale intent, synchronizes the Dock and Media Session to paused, and gives a one-line recovery notice.
- Visible native focus pauses immediately reconcile intent; hidden-page pauses preserve the captured resume intent.
- Interrupted crossfade DOM is collapsed to the active player before return recovery.
- Late recovery results are fenced by lifecycle generation so a second background transition cannot restart hidden audio.
