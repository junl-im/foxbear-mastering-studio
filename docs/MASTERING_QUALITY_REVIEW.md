# 마스터링 품질·메모리 개선 검토

검토일: 2026-10-10 (Asia/Seoul). GitHub main의 정적 검토이며 로컬 미동기화 변경, 청취 결과, 실행 성능은 확인하지 않았다. 이 문서는 개선 설계이며 엔진 수정 완료 보고가 아니다.

## P1: 음질 검사 샘플링

`src/audio/mastering-quality-audit-service.js`의 inspect는 `ceil(buffer.length / 65536)` 간격으로 샘플을 읽는다. 연속 샘플이 아닌 값의 차이로 highProxy를 계산하고, 안티앨리어싱 없이 간격을 늘린 신호에 저역 필터를 적용한다. 따라서 곡 길이에 따라 주파수 지표가 달라질 수 있다. effectiveRate를 최소 1000으로 제한하여 실제 추출 주파수와 필터의 시간축이 달라지는 경우도 있다. invalid와 peak 역시 선택된 위치만 검사하므로 전체 출력 무결성을 보장하지 않는다.

개선: 분산된 연속 구간을 원래 sampleRate로 분석하고 구간 경계에서 필터와 이전 샘플 상태를 초기화한다. 전체 샘플 무결성 검사는 기존 파이프라인에 있는지 확인한 뒤 별도 책임으로 둔다. UI 스레드의 전체 스캔을 무조건 추가하지 않는다.

검증 조건: 같은 정상상태 신호의 짧은/긴 버전에서 고역·저역 지표가 일치해야 한다. 추출 간격에서 누락되는 위치에 넣은 NaN/Infinity와 단발 피크를 출력 안전 검사에서 검출해야 한다. 무음·모노·역상·피치/길이 변경 케이스와 기존 quality gate 임계값도 재검증한다. proxy 값만으로 청감 품질을 단정하지 않는다.

## P1: 음량 측정의 추가 메모리

`src/audio/loudness-measurement-service.js`의 makePower는 전체 길이의 Float64Array를 만든다. 48000 Hz × 600초 × 8바이트 = 230400000바이트(약 230MB 또는 220MiB)의 추가 배열이다. 원본 PCM 등은 이 수치에 포함하지 않았다. 실제 동시 호출 및 경로별 사용량은 추가 확인이 필요하다.

개선: 필터 상태를 유지하며 청크별 에너지 합과 샘플 수를 축적한다. integrated의 400ms/100ms hop과 short-term 창을 공유할 수 있도록 설계한다. 길이 비례 PCM 배열을 없애되 기존 부분 창 처리의 의미 변경은 별도 결정으로 분리한다. cancellation/yield 및 Worker 실행 경로와 통합한다.

검증 조건: 기존 구현과 44.1/48/96kHz, 무음, 짧은 음원, 청크 경계 전후 길이, 페이드에서 결과를 비교한다. 첫 단계는 수치 호환성을 유지하며 표준 적합성 주장은 별도 기준 구현과 비교 후 결정한다. 10분 음원과 일괄 작업에서 피크 메모리·취소 응답성을 측정한다.

## P2: 레퍼런스 신뢰도 표시

`src/audio/reference-profile-service.js`의 buildReferenceMatch2는 기본 72에 spectrumProfile64 배열 존재 시 각각 10을 가산한다. 실제 사용 가능한 프로필은 길이 8 이상을 요구하지만 신뢰도 가산은 배열 존재만 확인한다. 누락된 특징값은 기본값으로 대체되므로 불완전한 데이터가 높은 유사도나 신뢰도로 보일 수 있다. 이 수치는 통계적으로 검증된 확률이 아니다.

개선: 유효 프로필, 측정된 특징의 비율, 분석 시간과 무음 비율을 반영한다. 데이터 부족은 unavailable로 구분한다. UI에서는 분석 근거 충실도와 유사도를 별도로 설명한다.

검증 조건: 빈 배열·누락 특징·무음에서 신뢰도가 올라가지 않아야 한다. 정상 프로필과 합성된 7대역 대체 프로필을 구분한다. 실제 청취 평가 전에는 확률로 표현하지 않는다.

## P2: 구조와 테스트

`src/app.js`는 약 779KB다. 크기만으로 성능 결함을 단정할 수 없지만 재생·렌더·UI 책임과 전역 의존성을 추적한 뒤 경계 단위로 분리할 후보이다. 기존 모듈과 책임이 중복되지 않도록 한다.

`qa/ab_loudness_difference_smoke.js`는 문자열 존재를 검사한다. 해당 검사는 유지할 수 있지만 실제 음량 일치·동기화의 검증을 대체하지 않는다. 다른 동작 테스트가 커버하는 범위를 먼저 확인하고 부족한 부분만 합성 신호 및 브라우저 테스트로 추가한다.
