# v1.5.65 Incident Recovery Control, Alert Channels, and Operations History

## 목적

v1.5.64는 SMTP/Secret과 장기 미발송 상태를 감지했지만, SMTP 자체가 고장 난 순간에는 같은 메일 채널로 경보를 전달할 수 없었습니다. 또한 자동 재시도 스케줄러가 실제로 몇 건을 처리하고 성공·실패했는지 장기적으로 확인하기 어려웠고, 관리자는 보고서별 버튼을 반복해서 눌러야 했습니다.

v1.5.65는 외부 경보 채널과 관리자 일괄 복구, 자동 복구 실행 통계, 30일 운영 이력을 추가합니다.

## 진행된 개선

- 선택적 `FOXBEAR_INCIDENT_ALERT_WEBHOOK_URL` 환경 변수를 지원합니다.
  - HTTPS만 허용합니다.
  - Slack, Discord, Google Chat, Microsoft Teams 계열의 승인된 호스트만 허용합니다.
  - 웹훅 URL과 원문 오류 보고 내용은 Firestore 운영 문서에 저장하지 않습니다.
  - 전송 내용은 SMTP 상태, 장기 미발송 수, 최종 실패 수, KST 발송 한도 같은 집계 정보만 포함합니다.
- SMTP가 실패해도 웹훅이 준비된 경우 운영 경보와 복구 알림을 독립적으로 전송합니다.
- 외부 채널이 모두 불가능한 경우에도 `incidentOperations/mail`과 운영 이력에 상태를 남깁니다.
- `incidentOperationsHistory`에 30분 단위 운영 스냅샷을 최대 30일 보존합니다.
- 운영 경보 시도는 `incidentOperationsAlerts`에 채널별 성공·실패 상태로 기록합니다.
- 자동 재시도 스케줄러와 관리자 일괄 복구 결과를 `incidentOperations/recovery`에 기록합니다.
  - 요청 건수
  - 실제 시도 건수
  - 발송 성공
  - 실패
  - 최종 실패
  - 임대/중복으로 건너뛴 건수
  - 실행 시간
- 관리자 오류 화면에 다음 기능을 추가합니다.
  - `미발송 일괄 복구`
  - `최종 실패 일괄 재전송`
  - 최근 자동 복구 결과
  - 보조 경보 상태
  - 최근 24시간 주의·위험 추세
- 일괄 복구는 한 번에 최대 8건을 처리하며 기존 임대 ID, 일일 한도, 중복 억제 계약을 그대로 사용합니다.
- 새 이력 규칙이 아직 배포되지 않은 순차 배포 상황에서는 관리자 화면이 이력 없이 계속 열리도록 폴백합니다.

## 설정

`functions/.env` 또는 Firebase Functions 환경 설정에 선택적으로 아래 값을 등록합니다.

```text
FOXBEAR_INCIDENT_ALERT_WEBHOOK_URL=https://...
```

설정하지 않아도 기존 Gmail 발송과 Firestore 운영 화면은 정상 동작합니다. 잘못된 URL이나 허용되지 않은 호스트는 운영 상태에서 주의로 표시됩니다.

## 배포

```bash
firebase deploy --only firestore:rules,firestore:indexes,functions:sendIncidentEmail,functions:retryFailedIncidentEmails,functions:retryIncidentEmailRequest,functions:retryIncidentBatchRequest,functions:sendDailyIncidentSummary,functions:auditIncidentMailOperations
firebase deploy --only hosting
```

## 제한 사항

- 실제 웹훅 응답과 Gmail 수신은 각 서비스의 실제 URL, Firebase 프로젝트 권한, 배포된 Functions 환경에서 최종 확인해야 합니다.
- 관리자 일괄 복구는 안전한 실행 시간과 Gmail 한도를 위해 한 번에 8건까지만 처리합니다. 남은 건은 다음 스케줄 또는 다음 관리자 요청에서 이어집니다.
- 운영 이력은 오류 원문, 파일명, 오디오, 사용자 입력 내용을 저장하지 않고 집계 상태만 저장합니다.
