# v1.6.74 Incident Admission, Spark Retention, and Download Memory Closure

## Why this release exists

v1.6.73 closed the initial audio-import decoded-memory gap and strict-CSP 404 recovery. The follow-up audit found three remaining operational boundaries: public incident submission could create reports without a server admission budget, Spark-only Firestore fallback reports could remain pending without an initial TTL field, and post-master alternate-format downloads could re-decode a completed output without passing the new memory limits.

## Incident admission

`submitIncidentReport` now checks an existing deterministic report document before consuming quota. New submissions pass through a Firestore transaction that maintains per-UID minute, hour, and KST-day counters plus global minute/hour counters in `incidentMailState`. Manual mail tests have a separate daily ceiling. The admission state carries a short `expiresAt` and reuses the existing `incidentMailState.expiresAt` TTL policy.

The server-only `incidentMailState/admissionControl` document supports `mode: enabled | degraded | disabled`. Reads are cached briefly. `degraded` halves the normal admission ceilings and `disabled` rejects new Callable report creation. The public Callable also declares a finite `maxInstances` ceiling.

## Spark fallback retention and status

Direct Firestore compatibility submissions now write `submissionTransport: firestore-fallback` and an approximately 30-day `expiresAt` at creation. Firestore Rules require that provenance value and constrain the TTL to a narrow 29-31 day window. When the Callable status path is unavailable and the fallback document is still pending, the client exposes `stored-no-mail-service` instead of presenting the record as ordinary SMTP processing.

## Download re-decode memory closure

When completed mastered PCM has already been released and an alternate download format needs to decode `outBlob` again, the download service now resolves the runtime low-memory/standard device policy and passes both `maxDecodedPcmBytes` and `maxDecodePeakBytes` into the shared audio decode service.

## KST quota alignment

The browser automatic-incident daily counter now rolls over at Korea Standard Time midnight, matching the server email/admission day boundary rather than UTC midnight.

## Operational notes

- App Check remains disabled by release policy.
- Keep Firestore TTL enabled on `incidentReports.expiresAt` and `incidentMailState.expiresAt`.
- The global admission cap limits service-wide bursts but is not a replacement for App Check or upstream Firebase abuse controls.
- Spark-only direct Firestore fallback remains intentionally best-effort; Firestore Rules cannot provide the same cross-document rolling-rate-limit guarantees as the Callable path.
