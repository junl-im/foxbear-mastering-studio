# v1.6.61 Human-Readable Cross-Platform Download Filenames

## User-visible result

Input:

`천 개의 파랑 (A Thousand Blues).wav`

Mastered WAV24 output at -15 LUFS with the streaming style:

`천 개의 파랑 (A Thousand Blues) mastered 15LUFS streaming wav24.wav`

## Root cause

The previous output builder used an ASCII/Hangul allowlist and replaced every other title separator with `_`. The metadata builder also joined every generated token with `_`. This made valid spaces and parentheses disappear even though modern browser downloads and ZIP entries support them.

## Design

`src/download/file-name-policy-service.js` owns the filename contract for:

- normal mastered downloads
- alternate WAV/MP3 conversion downloads
- per-track sequential export
- ZIP export planning
- ZIP worker entry normalization and duplicate handling

The policy normalizes Unicode to NFC, strips control and bidirectional/invisible formatting characters, replaces only `\\ / : * ? \" < > |` with spaces, collapses repeated whitespace, removes unsafe leading/trailing dots and spaces, and protects Windows reserved names.

## Length and collision rules

- Maximum generated filename length: 240 UTF-8 bytes.
- Metadata and extension are preserved; only the source-title portion is shortened.
- ZIP duplicate names use ` (2)`, ` (3)`, and later suffixes.
- Duplicate detection is case-insensitive.

## Legacy compatibility

Older FoxBear exports such as:

`천_개의_파랑_A_Thousand_Blues__mastered_15LUFS_streaming_wav24.wav`

are humanized and the previous generated suffix is removed before a new suffix is added. Parentheses that were already destroyed by the older filename cannot be reconstructed, but duplicate mastering labels are prevented.

## Exceptions and limitations

- Browsers or operating systems may visually hide `.wav` or `.mp3` extensions.
- Existing old files cannot recover punctuation that was already removed in a previous download.
- Cloud storage providers may apply their own additional normalization after download.
- File-system behavior still requires real-device acceptance on Windows, macOS, Android, and iOS.

## Regression coverage

`qa/v1661_human_readable_download_filename_smoke.js` verifies the exact Korean/English example, legacy suffix cleanup, forbidden characters, Windows reserved names, trailing dots/spaces, UTF-8 byte limits, duplicate ZIP names, and integration with app/download/export/worker paths.
