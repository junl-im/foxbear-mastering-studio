# v1.6.47 External-host administrator authentication and opaque error recovery

## Confirmed incident

The production screenshot reported `host=jurl-img.github.io` with `authDomain=foxbear-music.firebaseapp.com`. The Google account chooser completed, but Firebase returned `auth/network-request-failed`. The previous recovery then attempted `signInWithRedirect()` from a non-Firebase host. Redirect authentication depends on Firebase authentication helper storage; on a host such as GitHub Pages, that helper is cross-origin unless a reverse proxy or self-hosted helper is provided.

The separate `앱 실행 오류: Script error.` banner was an opaque cross-origin `window.error` event without a filename, stack, line, or actionable application error. It should not overwrite the audio import status or classify the local application as broken.

## Recovery design

- Keep `signInWithPopup()` as the first path on external hosts.
- Do not call `getRedirectResult()` on GitHub Pages or other non-Firebase Hosting origins.
- After popup `auth/network-request-failed`, wait briefly for a delayed Google `onAuthStateChanged` result before declaring failure.
- Permit `signInWithRedirect()` only on the two approved Firebase Hosting origins.
- If external-host popup recovery does not settle, move to `https://foxbear-music.web.app` with a fixed `foxbearAdmin=1` marker.
- Reuse the existing bounded session handoff service so non-audio settings survive the origin change.
- Automatically reopen the administrator access dialog on the secure origin, while requiring a fresh user click for the Google account chooser.
- Treat opaque cross-origin `Script error.` events as runtime warnings only. Same-origin errors with a real Error object, source, or stack still reach the visible application error path.

## Security boundaries

- The secure fallback hostname is hard-coded and validated as `https://foxbear-music.web.app`; no user-controlled open redirect is accepted.
- OAuth tokens, query values, popup credentials, and Google account data are not placed in the handoff payload.
- The one-attempt redirect loop fence remains active on Firebase Hosting.
- App Check remains disabled by policy.
- Firestore administrator authorization remains an active matching `siteAdmins/{UID}` document after Google Authentication succeeds.
