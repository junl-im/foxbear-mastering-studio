# v1.5.76 Atomic Release Sync and Dependency Health

## Problem

The release metadata tool previously wrote many runtime, QA, manifest, Functions, service-worker, and SRI files directly. A late Python/SRI or validation failure could leave the repository in a partially synchronized state. The root lockfile version was also outside the automatic synchronization path.

## Changes

- Copy the project into an isolated temporary staging workspace.
- Run metadata updates, SRI normalization, and full version validation inside that workspace.
- Compare staged output with the source and expose an exact `--dry-run` file list.
- Commit validated files with per-file atomic replacement and rollback already-written files if a commit error occurs.
- Synchronize both root and Functions lockfile version fields.
- Add dependency health checks for manifest/lock contracts, installed direct dependencies, Playwright runtime, and Chromium availability.
- Remove tracked Python bytecode caches, ignore future `__pycache__` output, and declare deletion paths for overwrite handoffs.

## Failure contract

Setting `FOXBEAR_PYTHON_BIN` to an unavailable executable forces the staged SRI boundary to fail. The parent process must return non-zero and leave protected source files byte-for-byte unchanged.
