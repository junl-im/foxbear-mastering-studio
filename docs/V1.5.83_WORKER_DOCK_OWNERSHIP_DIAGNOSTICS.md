# v1.5.83 Worker Lifecycle and Dock Ownership Diagnostics

## Problem

During a rapid track change, the old Dock media element could still be mounted when the new selected track began rendering. The transport capture path accepted the new track object while reading time from the old audio element, allowing the previous song's position to become the new song's restore lease. Old crossfade audio events could also resynchronize MediaSession after the new audio became active. Worker jobs were cancellable but did not expose active lifecycle counts, making long-session cleanup difficult to verify.

## Fix

- Resolve audio ownership from playback/spectrum track datasets before transport capture or MediaSession synchronization.
- Reject cross-track transport writes and route inactive crossfade events to the current active Dock audio.
- Record active Worker jobs and bounded completion history, including stage, progress, elapsed time, and estimated remaining time.
- Remove active Worker records on every completion, cancellation, timeout, postMessage failure, and Worker error path.
- Abort mastering and master-preview controllers from generic track resource cleanup.
- Remove stale playback track datasets during unregister.
