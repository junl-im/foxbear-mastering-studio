# v1.6.41 Administrator Secret PIN Session

## Scope

This patch exposes the existing administrator monitoring surface from Settings without embedding the administrator PIN in any browser-delivered file. It does not change mastering DSP, encoders, audio payload handling, incident email contents, or monitoring data schemas.

## Security model

- The real PIN is registered interactively as the Firebase Secret Manager secret `FOXBEAR_ADMIN_ACCESS_PIN`.
- The browser sends the entered value through the authenticated Callable Function `unlockAdminAccess`; no client-side equality check exists.
- The function compares fixed-length SHA-256 digests with `timingSafeEqual` and never logs the candidate or configured secret.
- Attempts are counted independently for the anonymous Firebase UID and a SHA-256 network fingerprint. The raw network address is not stored.
- Five failures inside a ten-minute window trigger a fifteen-minute lock.
- Success writes an eight-hour `siteAdmins/{uid}` session. Firestore Rules and administrator Functions both reject an expired session.
- Optional App Check enforcement can be enabled with `FOXBEAR_ADMIN_REQUIRE_APP_CHECK=true` after the production web App Check key is configured.

## User flow

1. Open Settings.
2. Select `관리자 모니터링`.
3. Enter the administrator password.
4. On server verification success, the existing visit and incident monitoring dialog opens.
5. The same anonymous browser session can reopen it until the eight-hour grant expires.

## Deployment

```bash
firebase login
firebase use foxbear-music
firebase functions:secrets:set FOXBEAR_ADMIN_ACCESS_PIN
npm run deploy:incident
```

The secret command prompts for the real value without putting it in the repository or shell command arguments. Configure Firestore TTL on `adminAccessAttempts.expiresAt`.

## Regression contract

- `node qa/v1641_admin_secret_pin_session_smoke.js`

## Remaining production gates

- Register the actual secret in the target Firebase project.
- Deploy the Callable Function and Firestore Rules.
- Confirm anonymous Authentication is enabled.
- Run a successful and failed unlock from the production domain.
- Configure and enforce App Check after validating the production site key.
