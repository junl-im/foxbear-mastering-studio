# v1.6.10 Incident Readiness Contract, CSP, and Cache Hardening

## Scope

This patch removes false healthy states from incomplete readiness responses and hardens local diagnostic persistence.

## Changes

- Requires every Functions, Firestore, Gmail Secret, and SMTP check to exist with an explicit boolean result.
- Requires a valid check timestamp, server product version, and Callable origin before readiness can be healthy.
- Converts malformed success payloads into `FOXBEAR_INCIDENT_READINESS_CONTRACT_INVALID` recovery guidance.
- Refuses to reuse malformed server-side cached readiness documents.
- Parses the CSP `connect-src` directive and compares normalized origins exactly.
- Marks local cooldown reuse as cached and updates the existing history item by `checkedAt`.
- Filters null, scalar, invalid-date, and unknown-check local history data.
- Persists the final three-section delivery rule requested by the user.
