# v1.6.83 Browser Gate UI-Mode Fixture and Source Hygiene Recovery

## Incident

GitHub Actions runs #269 and #270 both reported the same browser-gate shape: two cases failed on the primary run, failed again on the failed-only retry, and remained unresolved in browser history. The immediately preceding v1.6.79 run succeeded.

The change boundary that first introduced the repeated failure also introduced the required first-entry AI Mastering / Expert workspace chooser. Existing Playwright scenarios were written before that chooser and used `navigateToApp()` without selecting a workspace, so unrelated clicks could be intercepted by the required modal overlay in both desktop and mobile projects.

## Recovery

`qa/browser/helpers/foxbear-e2e-helpers.js` now establishes a deterministic browser-fixture workspace before product scripts run:

- Default E2E workspace: `expert`.
- Explicit AI workspace: `navigateToApp(page, { uiMode: 'ai' })`.
- Real first-entry chooser: `navigateToApp(page, { uiMode: false })`.
- The selected fixture mode is exposed as `window.__FOXBEAR_E2E_UI_MODE__` for diagnostics.

This keeps production first-entry behavior intact while isolating legacy browser scenarios from a new mandatory onboarding layer.

## Source hygiene

The repository history still contained a legacy generated `PATCH_MANIFEST.json`. CI safely deleted it in the ephemeral checkout but emitted a warning because the deletion had not been committed. Patch delivery now always contains both `APPLY_PATCH_CLEANUP.sh` and `APPLY_PATCH_CLEANUP.cmd`; `DELETE_PATHS.txt` continues to list `PATCH_MANIFEST.json`.

After applying the patch on Windows, run `APPLY_PATCH_CLEANUP.cmd` before committing in GitHub Desktop. On macOS/Linux, run `bash APPLY_PATCH_CLEANUP.sh`.
