# v1.6.23 Full Audit, Persisted Route Decay, Lifecycle Safety, and Handoff Contract

## Audit scope

- System: boot order, service-worker asset generation, release metadata, packaging, Firebase incident recovery, local persistence, and handoff verification.
- Performance: mastering Worker fast paths, golden-audio benchmarks, queue/ZIP memory guards, lifecycle recovery coalescing, and static-suite execution cost.
- Technology: plain JavaScript browser modules, Web Audio/Workers, Firebase Functions/Firestore, PWA caching, SRI, Playwright, and GitHub Actions.
- Features and engine: import, analysis, mastering/finalizer, recommendation, preview translation, export/download, incident reporting, and administrator diagnostics.
- Failure handling: offline/online transitions, connection changes, long resume, corrupt local storage, callback rejection, stale release documentation, packaging hygiene, and archive verification.

## Confirmed defects

1. Elapsed-time route score decay was calculated by `getHealth()` but was not persisted unless a network change also occurred. A later success or failure write could reload the pre-decay counters and revive stale evidence.
2. Route mutation methods did not apply elapsed-time decay before recording new attempts, successes, or failures.
3. Lifecycle event listeners passed async handlers directly to browser events. A rejected callback could become an unhandled Promise rejection because event dispatch does not consume returned Promises.
4. `version:check` and `handoff:check` accepted a current `HANDOFF.md` title while the first Current release block still described v1.6.21. The GitHub Desktop guide also lacked a current-version title check.
5. The mandatory three-section delivery rule existed in historical handoff text but had no dedicated immutable document or package-gate validation.

## Changes

- Route state preparation now applies and persists both time decay and network decay before reads and writes.
- Route timestamps and cooldowns share the supplied clock, improving deterministic tests and avoiding stale evidence resurrection.
- Browser lifecycle listeners now contain synchronous throws and asynchronous rejections, report sanitized phase diagnostics through `onError`, and retain direct handler rejection semantics for explicit callers.
- Release metadata validation now checks the first handoff Current release block, current configured QA target, GitHub Desktop guide version, and delivery-rule document.
- Packaging includes `DELIVERY_RULES.md`; the handoff manifest requires the rule, this audit document, and the v1.6.23 regression.

## Risk and compatibility

- Audio DSP samples, mastering targets, encoders, recommendation scoring, and exported formats are unchanged.
- Route history schema advances to 5 but remains backward-compatible because stored values are normalized field by field.
- Local storage failure remains fail-soft; decayed state is still returned for the current call even when persistence is unavailable.
- Production Firebase, App Check, Gmail receipt, installed-browser UI, and real-device background behavior remain deployment/device gates.

## Category findings

### System

- Boot script ordering, SRI, service-worker cache generation, runtime asset presence, release metadata, handoff manifest, GitHub Actions contracts, and archive hygiene passed the cumulative gate.
- The release remains a static PWA with Firebase-backed incident services. Hosting and Functions must still be deployed from the same release when incident routes change.
- The release and overwrite archives are root-safe: no nested project directory, `node_modules`, transient logs, Python bytecode, test artifacts, or symlinks are included.

### Performance

- No audio DSP hot loop changed in v1.6.23. Existing zero-copy channel reuse, shared K-weighted measurement, True Peak reuse, Worker cancellation, memory guard, and ZIP Worker contracts passed.
- Engine QA synthetic realtime ratios remained positive across balanced pop, metallic vocal, mobile-boom, and peak-stress cases.
- Lifecycle recovery continues to coalesce simultaneous triggers; the patch only hardens state preparation and event error containment.
- The cumulative dependency-light suite is intentionally large and completed 355 checks; installed-browser runs remain a separate release gate.

### Technology

- Browser JavaScript syntax, Functions syntax, Python bytecode hygiene, SRI, local dependency metadata, Playwright fixture contracts, and release metadata passed.
- The sandbox did not contain a valid installed `@playwright/test` or Functions dependency tree. Dependency-health checks therefore passed with installation warnings rather than installed-package verification.
- No production Firebase, SMTP, App Check, or Gmail credentials were accessed during this audit.

### Features

- Import, queue control, analysis, recommendation, preview translation, playback, waveform, modal, bulk mastering, export, download, ZIP, PWA update, incident reporting, administrator diagnostics, and recovery contracts passed their configured regressions.
- The mandatory result format is now stored independently in `DELIVERY_RULES.md` and is required in both archives.

### Engine

- Engine QA and golden-audio packs passed without changing DSP source behavior.
- Golden cases retained the expected target behavior: acoustic natural, sibilant vocal, bass-heavy mobile, and wide electronic outputs all reported final integrated loudness at -14.00 LUFS in the configured harness.
- Peak-stress safety retained the configured -1.00 dBTP ceiling behavior in the synthetic engine bench.

### Problems, bugs, and exceptions

- Fixed stale route evidence resurrection caused by non-persisted time decay.
- Fixed mutation paths that previously skipped time decay.
- Fixed the short-circuit risk where one decay class could suppress the other in a shared preparation pass.
- Fixed browser event-bound callback rejection leakage.
- Fixed release gates that accepted stale handoff body metadata.
- Fixed the historical v1.6.22 regression so it validates a current build-ID contract instead of pinning an obsolete build ID.
- Remaining exceptions are environment-bound: real Chromium rendering, installed PWA upgrades, mobile background/resume, production Firebase/App Check, and Gmail delivery.
