# v1.6.38 UI Shell Runtime Health and Cache Retirement

## Scope

This patch hardens the v1.6.37 emergency UI-shell recovery without changing mastering DSP, encoders, download formats, Firebase document fields, or incident payloads.

## Changes

- Treat core stylesheets as pending until the window load boundary or an explicit resource error, avoiding a false safe-UI warning during normal loading.
- Resolve and remove the safe-UI state after styles become available again.
- Suppress the standalone shell notice while the Runtime Health recovery panel is visible, so users receive one recovery surface instead of two overlapping notices.
- Include bounded UI-shell recovery state in Runtime Health reports and keep the recovery panel visible when app initialization completes in a degraded style state.
- Let controlled pages answer service-worker shell-generation probes.
- Retain two generations when any controlled page cannot report its shell version, preserving compatibility with older open tabs.
- When every controlled page reports successfully, retire the inactive older retained generation while keeping the current cache and latest rollback cache.

## Regression contract

`node qa/v1638_ui_shell_runtime_health_cache_retirement_smoke.js`

The regression covers pending-versus-failed style classification, notice deduplication, recovery resolution, client generation reporting, and client-aware legacy cache retirement.
