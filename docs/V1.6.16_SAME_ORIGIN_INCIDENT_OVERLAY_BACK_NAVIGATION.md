# v1.6.16 Same-Origin Incident Recovery and Overlay Back Navigation

## Incident transport chain

1. Firebase `httpsCallable` remains the primary transport.
2. Network, CORS, unavailable, or deadline failures attempt an authenticated same-origin Hosting rewrite.
3. Incident submission and delivery lookup retain the existing Firestore owner-scoped compatibility fallback.

The same-origin request uses the standard Callable JSON envelope, the current anonymous user's Firebase ID token, and the App Check token when configured. It never sends audio, filenames, local paths, report-body copies, Gmail credentials, or Firebase Secret values as diagnostic metadata.

## Hosting rewrites

- `/api/incident/status` -> `getIncidentServiceStatus`
- `/api/incident/submit` -> `submitIncidentReport`
- `/api/incident/delivery` -> `getIncidentDeliveryStatus`
- `/api/incident/readiness` -> `checkIncidentDeploymentReadiness`

All routes target `asia-northeast3`. Deploy Hosting and Functions together with `npm run deploy:incident`.

## Overlay policy

Interactive child dialogs opened from an existing layer join the shared fixed overlay stack. The parent stays mounted, becomes inert, and resumes after the child closes. Passive hover tooltips remain outside the blocking stack. One browser-history sentinel allows mobile Back to dismiss the top blocking overlay before page navigation. Overlay-consumed `popstate` events are marked and ignored by the existing unsaved-work exit guard.

## QA

Run `node qa/v1616_same_origin_incident_overlay_navigation_smoke.js`, then the cumulative static gate. Production verification still requires installed browsers, real mobile Back behavior, deployed rewrites, Functions logs, and Gmail receipt confirmation.
