# v1.6.65 Firestore Write Fencing and Daily Visit Deduplication

## 문제

기존 방문 기록은 `addDoc()`의 무작위 문서 ID를 사용했습니다. 클라이언트 세션에서는 한 번만 기록했지만 새로고침, 새 탭, 변조된 클라이언트에서는 같은 익명 UID가 하루 동안 여러 `siteVisits` 문서를 만들 수 있었습니다.

문제 신고는 정상 클라이언트에서 `UID_submissionKey` 형식을 사용했지만 Firestore Rules는 문서 ID와 `submissionKey`의 일치를 강제하지 않았고, Callable도 UID 접두사만 맞으면 호출자가 선택한 ID를 받아들일 수 있었습니다.

## 적용 내역

- 방문 문서 ID를 `Firebase UID_YYYY-MM-DD`로 고정했습니다.
- 같은 UID의 같은 날짜 재기록은 기존 문서를 확인한 뒤 중복 제거 성공으로 반환합니다.
- 방문 날짜는 `YYYY-MM-DD` 형식이어야 하며 문서 ID가 UID와 날짜로 계산한 값과 정확히 같아야 합니다.
- 신고 `submissionKey`는 제한된 영숫자·밑줄·하이픈 형식이어야 합니다.
- 신고 문서 ID는 `request.auth.uid + '_' + submissionKey`와 정확히 일치해야 합니다.
- Callable은 정규화된 제출 키로 canonical ID를 계산하고, 호출자가 다른 ID를 보내면 `invalid-argument`로 거부합니다.

## 기대 효과

- 익명 UID당 방문 문서 생성량을 하루 1개로 제한합니다.
- 새로고침 시 불필요한 방문 문서 증가를 막습니다.
- 신고 중복 제거 키와 저장 문서 ID 사이의 우회 경로를 제거합니다.
- Callable과 Firestore 직접 호환 경로가 동일한 ID 계약을 사용합니다.

## 호환성

- 기존 방문·신고 문서는 변경하거나 삭제하지 않습니다.
- 새로 생성되는 문서부터 강화된 규칙이 적용됩니다.
- App Check는 아직 강제하지 않으며 다음 단계에서 모니터링 기반 도입을 검토합니다.
