# v1.6.49 Download Variant Cache Reuse

## Problem

After v1.6.48 made every MP3/WAV quality selectable after mastering, requesting the same alternate format again repeated the completed-output decode and encoder work. Long tracks could therefore incur the same delay and temporary PCM memory pressure for download, share, and reopened-dialog flows.

## Patch

- Cache the newest successfully verified alternate-format Blob for each mastered source Blob.
- Reuse it only when the requested format and source output format match exactly.
- Keep at most one variant and skip cache storage above 64 MB.
- Never cache a fallback output when the encoder returns a different format from the requested format.
- Rebuild the file name from current track metadata at use time.
- Display cached variants as immediate reuse and use their exact Blob size.
- Distinguish MP3-to-MP3 lossy re-encoding guidance from MP3-to-WAV no-restoration guidance.

## Safety

The cache is a `WeakMap` keyed by the completed source Blob. Replacing or releasing the mastered output removes the last strong source reference, allowing the source and its one cached variant to be collected together.
