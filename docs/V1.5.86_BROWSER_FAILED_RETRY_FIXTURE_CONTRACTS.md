# v1.5.86 Browser Failed-Only Retry & Fixture Contracts

## 문제

브라우저 QA 소스 사전 검사는 Playwright 실행기 내부에 있었기 때문에 GitHub Actions가 Chromium과 시스템 패키지를 설치한 뒤에야 실행됐다. 또한 첫 브라우저 실행이 일부 케이스에서 실패하면 같은 job 안에서 실패 항목만 다시 확인하는 표준 경로가 없었다. 공유 시각 fixture가 실제 마크업 ID나 CSS 선택자 변경을 따라가지 못해도 Chromium 단계까지 가야 발견할 수 있었다.

## 변경

- `qa/browser/run-browser-preflight.js`가 안전 sink 검사와 production fixture 계약 검사를 한 번에 실행한다.
- GitHub Actions는 Chromium 설치 전에 `npm run qa:browser:preflight`를 실행한다.
- `qa/browser/fixture-contract-preflight.js`가 대량 마스터링 HUD와 다운로드 시트의 실제 DOM ID, UI 소스 토큰, CSS 선택자를 검증한다.
- Playwright output directory를 `qa/browser-results/artifacts`로 분리해 JSON 보고서와 서버 로그를 재실행 중에도 보존한다.
- `npm run qa:browser:retry`가 Playwright `--last-failed` 상태를 사용해 이전 실패 케이스만 한 번 재실행한다.
- 재실행 전 기본 JSON 보고서, 서버 로그, last-run 상태를 `*-primary` 파일로 보존한다.
- GitHub Pages 기본·fallback workflow 모두 primary browser gate 실패 시 failed-only retry를 실행한다.

## 검증

- 일반 실행은 전체 `qa/browser`를 대상으로 한다.
- `--last-failed` 실행은 전체 디렉터리 인수를 추가하지 않는다.
- 이전 실행 상태가 없으면 전체 재실행으로 조용히 대체하지 않고 명확한 오류를 낸다.
- production fixture 계약과 위험 sink 사전 검사가 Playwright 설치 없이 통과한다.
- primary 결과와 `.last-run.json` 보존 동작을 임시 파일 시스템에서 검증한다.
