# v1.5.61 워커 부팅 및 문제 보고 메일 복구 보고서

## 증상

- 마스터링 시작 시 `워커 작업 관리 서비스를 불러오지 못했습니다.` 오류가 발생했습니다.
- 문제 보고 또는 테스트 신고를 제출해도 Gmail 알림이 도착하지 않거나, Firestore 문서가 `pending`/`sending` 상태에 머무를 수 있었습니다.

## 확인된 원인

### 1. 워커 작업 관리 서비스가 HTML에서 로드되지 않음

`src/app.js`는 마스터링 워커를 실행할 때 `window.FoxBearWorkerJobService.run`을 필수로 사용합니다. 그러나 서비스 구현 파일 `src/utils/worker-job-service.js`가 존재하고 서비스 워커 캐시에도 포함되어 있었음에도, `index.html`에는 해당 스크립트 태그가 없었습니다. 따라서 새 페이지 부팅에서는 전역 서비스가 생성되지 않아 마스터링 시작 즉시 오류가 발생했습니다.

### 2. 메일 재시도 스케줄러가 일부 실패 상태를 회수하지 못함

기존 스케줄러는 `delivery.status == failed` 문서만 조회했습니다. 다음 경우에는 자동 복구가 되지 않을 수 있었습니다.

- Firestore 생성 트리거가 실행되지 않아 `delivery`가 없는 `pending` 문서
- 함수가 SMTP 처리 중 종료되어 임대 시간이 지난 `sending` 또는 `retrying` 문서
- 예약 트랜잭션 단계에서 일시적으로 실패한 문서

### 3. 수동 테스트가 실제 신규 메일을 항상 검증하지 못함

수동 테스트의 오류 지문이 시간 구간 안에서 재사용될 수 있어, 중복 억제 결과가 새로운 SMTP 발송 성공처럼 혼동될 여지가 있었습니다.

### 4. Firebase 준비 및 SMTP Secret 오류 진단이 부족함

- 클라이언트가 Firebase 브리지가 완전히 준비되기 전에 신고를 보내면 로컬 대기열로 넘어가도 원인이 명확히 표시되지 않았습니다.
- Gmail 앱 비밀번호가 비어 있거나 공백이 포함된 상태에서도 일반 SMTP 오류로만 보일 수 있었습니다.

## 반영한 수정

### 마스터링 워커

- `index.html`에서 `src/utils/worker-job-service.js`를 `src/app.js`보다 먼저 로드합니다.
- 워커 서비스 파일에 SRI 해시와 v1.5.61 캐시 버전을 적용했습니다.
- 런타임 필수 전역 목록에 `FoxBearWorkerJobService.run`을 추가했습니다.
- 서비스 워커 프리캐시와 배포 인계 manifest에 워커 서비스 파일을 필수 자산으로 등록했습니다.
- 회귀 방지 스모크 테스트가 로드 순서, SRI, 프리캐시, 런타임 전역을 함께 검사합니다.
- 의존성 설치 후 `functions/node_modules` 내부 심볼릭 링크 때문에 릴리스 ZIP 생성이 잘못 중단되지 않도록 패키징 검사 제외 규칙도 보강했습니다.

### 문제 보고 메일

- 수동 테스트마다 고유 `manual-test-<id>` 지문을 생성합니다.
- Firebase 준비를 최대 15초 기다리고 준비/오류 이벤트를 구분합니다.
- 신고 제출 후 메일 상태 확인 시간을 45초로 늘리고, 상태 조회 실패와 단순 처리 지연을 구분합니다.
- SMTP 연결/인사/소켓 타임아웃을 설정했습니다.
- Gmail 앱 비밀번호의 공백을 제거하고 16자 미만이면 `FOXBEAR_GMAIL_SECRET_INVALID`로 명확히 기록합니다.
- 15분 재시도 작업이 최근 신고 중 아래 상태를 회수합니다.
  - 2분 이상 지난 `pending` 또는 delivery 미생성 문서
  - 재시도 시각이 지난 `failed` 문서
  - 임대 시간이 지난 `sending`/`retrying` 문서
- 같은 보고서의 만료된 예약을 다시 잡을 때 일일 예약 카운터가 중복 증가하지 않도록 수정했습니다.
- `mastering-memory` 신고 분류가 `unknown`으로 강등되지 않도록 클라이언트와 Firebase 허용 목록을 맞췄습니다.

## 검증 결과

- v1.5.61 전용 워커/메일 복구 스모크 테스트 통과
- 기존 문제 보고 및 App Check 스모크 테스트 통과
- 워커 기반 내보내기 진행 복구 테스트 통과
- 버전 일관성, SRI, 서비스 워커 캐시, handoff 계약 검사 통과
- 전체 QA 목록은 긴 단일 실행이 환경 제한 시간에 걸려 분할 실행했으며, 구성된 268개 검사를 모두 커버한 뒤 실패 항목 없이 통과했습니다.
- Playwright 실제 브라우저 부팅 검증은 실행 환경에서 Chromium 다운로드 DNS가 차단되어 수행하지 못했습니다. 이 제한은 코드 오류가 아니라 테스트 환경 제약입니다.

## 실제 메일 발송을 위한 배포 절차

소스 수정만으로 이미 배포된 Cloud Functions의 동작은 바뀌지 않습니다. 프로젝트 루트에서 다음 순서로 배포해야 합니다.

```bash
firebase functions:secrets:set FOXBEAR_GMAIL_APP_PASSWORD
npm install
npm --prefix functions install
npm run check:release
npm run deploy:incident
firebase deploy --only hosting
```

Gmail 앱 비밀번호는 일반 계정 비밀번호가 아니라 Google 계정에서 발급한 16자리 앱 비밀번호를 사용해야 합니다.

배포 후 앱의 문제 보고 설정에서 `테스트 메일`을 누르고 다음을 확인합니다.

1. 화면 결과가 `테스트 메일 발송 완료`인지 확인합니다.
2. Firestore `incidentReports/<reportId>/delivery.status`가 `emailed`인지 확인합니다.
3. `pending`이 2분 이상 유지되면 `retryFailedIncidentEmails` 배포 상태와 Functions 로그를 확인합니다.
4. `FOXBEAR_GMAIL_SECRET_INVALID`가 보이면 Secret을 다시 등록하고 Functions를 재배포합니다.

## 남은 확인 사항

현재 로컬 환경에는 실제 Firebase 프로젝트 Secret과 배포 권한이 없으므로, Gmail 수신 자체는 여기서 확정할 수 없습니다. 코드 경로와 재시도/진단 체계는 수정했으며, 최종 수신 확인은 위 배포 후 테스트 메일로 완료해야 합니다.
