# v1.5.97 Worker Recovery Diagnostics

## Scope

This release adds user-triggered recovery for Worker jobs that have not published progress for at least 15 seconds. Healthy active jobs are not cancelled.

## Runtime contract

- `cancelJob(identifier, reason)` targets one active run ID or logical job ID.
- `cancelStalledJobs(options)` selects only jobs whose progress age meets the stall threshold.
- Cancellation terminates the Worker, rejects the original promise with `AbortError`, records a cancelled recent job, and removes active transfer-byte accounting.
- The diagnostics UI confirms destructive recovery and reports the number of cancelled jobs in an ARIA live status.

## User guidance

The summary panel converts internal warning codes into Korean actions covering overlapping audio, interrupted audio contexts, retained PCM, Worker stalls, high transfer memory, long main-thread tasks, and decode errors.

## Regression

`node qa/v1597_worker_recovery_guidance_stress_smoke.js` runs 30 sequential synthetic jobs and one stalled job, then confirms active Worker count and active transfer bytes return to zero.
