# v1.6.40 UI Shell Retry Replacement Settlement

## Scope

This patch hardens boot-resource recovery when a failed critical script or stylesheet is retried by inserting a replacement DOM node. It does not change mastering DSP, encoders, download formats, Firebase document fields, incident payloads, or service-worker cache-retirement policy.

## Problem

- The previous shell checker inspected only the first matching `<script>` or stylesheet node.
- A failed original node could therefore keep the shell permanently degraded even after a replacement node loaded successfully.
- A replacement script inserted after the window load boundary could also be treated as loaded before its own `load` event.

## Changes

- Evaluates all matching critical resource nodes instead of only the first match.
- Treats any confirmed loaded replacement as authoritative over an older failed duplicate.
- Keeps post-load replacement nodes in a bounded `retrying` state until their own load/error settlement.
- Observes dynamically inserted critical resource nodes and starts retry settlement without requiring a manual recovery call.
- Uses a 2.5-second retry grace, then converts a replacement that produced neither load nor error into a confirmed failure.
- Keeps the recovery surface active while replacement loading is unresolved.
- Exposes `stylesRetrying` and `scriptsRetrying` in the UI-shell recovery snapshot.
- Clears retry and degraded classes after a replacement settles successfully.
