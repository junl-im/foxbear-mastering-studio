# v1.6.36 Service-Worker Activation Generation Fencing and Resource Stress

## Scope

- Fence competing cross-tab service-worker activation claims by token and generation.
- Delay `SKIP_WAITING` until a bounded claim-settlement window confirms final ownership.
- Reconcile a controller change missed while a page is frozen in BFCache.
- Coalesce concurrent managed AudioContext close requests.
- Stress Worker completion, failure, cancellation, and termination cleanup.

## Fixed failure modes

- Two tabs could both read an empty activation lease before either write and both later send `SKIP_WAITING`.
- A stale activation watchdog could clear or remove a newer lease owned by the same tab generation.
- A controller change occurring while BFCache-frozen could leave activation pending until timeout.
- UI disposal and page unload could call native `AudioContext.close()` concurrently on the same context.

## Contracts

- Activation leases contain a positive generation and release only when token and generation both match.
- A persistent claim waits 80 ms, re-reads ownership, rechecks peer idleness, then sends `SKIP_WAITING`.
- `pageshow` compares the current service-worker controller with the controller captured at activation.
- Duplicate `controllerchange` delivery is idempotent.
- Managed AudioContext close calls share one pending Promise and expose `closePending` diagnostics.
- Final delivery continues to follow `DELIVERY_RULES.md`.
