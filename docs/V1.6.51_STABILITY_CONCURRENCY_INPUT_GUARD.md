# v1.6.51 Stability, Concurrency, and Input Guard

## Audit findings

Two stability risks remained after v1.6.50:

1. The Kakao notice used a document-level capture listener while its full-screen layer allowed pointer events to pass through. The dismissal pointer could therefore close the notice and activate an upload, mastering, or download control underneath it.
2. Alternate-format preparation cached completed files, but two overlapping requests could still start duplicate decode/encode jobs. Passing a caller's abort signal directly into a shared implementation would also make one cancelled dialog terminate every waiter.

A third race was identified during the conversion audit: if the track's mastered Blob changed while conversion was running, a result could be cached against mutable track state rather than the exact source that produced it.

## Patch

### Kakao notice input and lifecycle safety

- The full-screen notice layer now receives pointer input and consumes the first dismissal gesture.
- `preventDefault()` and immediate propagation stop prevent background controls from receiving the same gesture.
- Touch scrolling is contained while the notice is visible.
- Re-executing the boot script reuses the existing API instead of creating a second layer.
- Orphaned notice DOM is removed before a fresh layer is created.
- Pointer, keyboard, page lifecycle listeners, timers, and DOM are released on dismissal or `pagehide`.
- The eight-second timeout, smooth transition, normal-browser suppression, PWA suppression, and external-guide suppression remain unchanged.

### Shared conversion job safety

- In-flight jobs are scoped by mastered source Blob, source format, and requested output format.
- Identical overlapping requests share one completed-file decode and one encode.
- Progress is broadcast to every active subscriber, including the latest progress replayed to a late joiner.
- Each subscriber has its own abort handling.
- Cancelling one subscriber does not abort the internal conversion while another subscriber remains.
- When the final subscriber cancels, the internal abort controller stops the decoder/encoder worker.
- Completed results continue to use the existing one-entry, 64 MB bounded variant cache.
- The job uses a source snapshot captured at start, preventing master replacement from cross-caching an old result under a new Blob.
