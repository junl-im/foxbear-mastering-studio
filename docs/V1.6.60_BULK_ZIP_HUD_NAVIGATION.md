# v1.6.60 Bulk ZIP Single-Archive Integrity and HUD Navigation

## Scope

This release addresses two user-visible failures after large mastering batches:

1. A ZIP request could be rejected by a conservative memory estimate and presented as an individual-download path.
2. The bulk mastering HUD could fail to follow the active row because it marked navigation complete before the newly rendered list had measurable layout.

## Root cause

### ZIP export

- The export guard treated estimated working-set pressure as a hard strategy switch.
- The estimate assumed more full-size copies than the current Blob-based STORE worker normally creates.
- The ZIP service returned an `individual` result on a blocked plan, which blurred the boundary between a ZIP request and the separate sequential-export action.
- Worker output integrity checked ZIP size but did not compare returned file count, worker size metadata, and the final delivery filename.

### Bulk HUD

- `lastAutoScrolledTrackId` was set before the scheduled animation frame executed.
- A render replacement, hidden/zero-height list, or filtered active row could therefore consume the one navigation attempt without moving the list.
- The callback retained the old row reference instead of resolving the active row from the latest DOM.

## Applied changes

### Single ZIP intent

- A ZIP button press now remains a single-archive operation. It never starts the individual export queue.
- Estimated memory pressure is a soft warning, not an automatic fallback trigger.
- Hard blocks remain aligned with the worker contract: more than 200 files or more than 1,500 MB of source data.
- Every plan exposes `singleArchiveRequired: true` and `automaticIndividualFallback: false`.
- The ZIP service reports `fallbackStarted: false` on success and failure paths.
- The worker result must match the requested file count and its reported size must match the returned Blob.
- The final delivered filename must remain `.zip`.
- The button copy now says `ZIP 다운로드 · 1개 파일`.

### Active HUD navigation

- New-track navigation cancels stale callbacks and uses a generation token.
- The active row is resolved again from the current list after rerender.
- Zero-height or disconnected layout retries are bounded to six attempts.
- Navigation is marked complete only after a measurable row is scrolled.
- A new active track returns to the `all` result filter when the current filter would hide it.
- The active row receives a short arrival highlight and centered scroll margin.

## Exceptions and safety boundaries

- A request above 200 files or 1,500 MB remains blocked because the worker itself rejects that payload.
- High-risk mobile ZIP generation can still fail from browser or OS memory termination. Failure remains a ZIP failure and does not silently start multiple downloads.
- KakaoTalk and other restricted in-app browsers may show the existing save/share assistant. The assistant still receives one ZIP Blob.
- The HUD respects an explicitly dismissed HUD; it does not reopen an overlay the user closed.
- Manual result-filter selection remains possible after the active row has been revealed.

- Added syntax checks for the export guard, ZIP service, application bridge, and HUD view.
- Release metadata, SRI, handoff state, archive integrity, and cumulative overwrite packaging are release gates.
