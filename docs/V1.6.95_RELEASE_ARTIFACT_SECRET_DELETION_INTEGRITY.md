# v1.6.95 Release Artifact Secret and Deletion Integrity

## Problem

The v1.6.94 release path was strict for tracked source state, but a Git-ignored `.env*` file could escape the Git-index-only hygiene view. The low-level ZIP builder also created its output before final verification, so a failed verification could leave a secret-bearing archive on disk. Separately, manifestless patch construction did not make Git deletions or rename sources part of its required delete contract, and Dock diagnostics could report a hidden Dock healthy while `selectedId` was stale and tracks still existed.

## Contract

- Source hygiene scans the physical worktree even when `.git` exists.
- Release ZIP construction runs strict hygiene before creating the archive, explicitly excludes `.env*`, and removes failed output archives.
- `package:delivery` never auto-repairs source state.
- Git deletions and rename sources are detected from `git diff --name-status -z -M HEAD` and must be covered by `DELETE_PATHS.txt`.
- Patch cleanup applies `DELETE_PATHS.txt` through a path-safety guard before the historical allowlisted hygiene repair.
- Dock health requires valid active selection whenever tracks remain, even if the Dock is hidden.

## Regression coverage

`qa/v1695_release_artifact_safety_smoke.js` reproduces ignored-secret blocking, Git delete/rename declaration, generic patch deletion application, and hidden-Dock stale-selection diagnostics.
