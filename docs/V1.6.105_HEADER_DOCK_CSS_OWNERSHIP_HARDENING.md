# v1.6.105 - Header / Dock CSS ownership hardening

## Problem

Header and Dock layout behavior was stable, but historical recovery patches still left large amounts of dead cascade state in `studio.css`, `mobile-native.css`, and `dock.css`. Many declarations were already guaranteed to lose to later declarations with the same selector/property, while legacy header selectors continued to coexist with the dedicated `header-command-bar.css` owner. This made future mobile/header/Dock edits harder to reason about and increased regression risk.

## Change

- Remove only Dock/Header declarations that are provably shadowed by a later declaration with the same selector, at-rule context, property, and equal-or-stronger `!important` priority.
- Remove legacy `.brand-topline*` and `.brand-right-actions*` ownership from `studio.css` and `mobile-native.css`; the live header DOM already opts into `brand-command-bar` / `brand-command-left` and is owned by `header-command-bar.css`.
- Add explicit Header and Dock ownership contract markers.
- Update historical source-string QA so it checks the current dedicated owner contracts rather than retired declarations in legacy stylesheets.
- Add a CSS complexity budget regression for the four affected owner/legacy files.
