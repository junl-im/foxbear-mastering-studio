# v1.6.28 Incident Lease Takeover, Fallback Sync, and Diagnostics UI Safety

## Scope

This patch hardens the browser-only anonymous incident queue when a tab is frozen, restored from BFCache, force-closed, or running in a browser that does not reliably provide `BroadcastChannel` or cross-tab storage events. It also removes direct incident diagnostic DOM mutation and status-event construction from the main reporter.

## System and lifecycle changes

- A stale localStorage lease is counted and reclaimed after expiry.
- `pagehide` releases active queue ownership immediately, including BFCache transitions, rather than keeping a peer blocked until the full lease TTL expires.
- `pageshow`, focus, and visible-state restoration trigger queue compaction, tombstone reconciliation, and ownership validation.
- Active lease ownership is aborted when another tab replaces the lock token.
- Failed lease renewal aborts the active operation because exclusive ownership can no longer be guaranteed.
- An expiry watchdog aborts work if heartbeat renewal cannot preserve the lease.

## Compatibility fallback

- A bounded revision poll supplements BroadcastChannel and storage-event synchronization.
- The fallback detects peer queue updates even when no browser event is delivered.
- Polling is stopped on coordinator disposal and exposes counters only, never queue contents.
- The diagnostics row identifies fallback synchronization and stale-lease takeover counts without exposing tab IDs or report data.

## UI responsibility split

`src/boot/incident-diagnostics-view-service.js` owns:

- seven-row service diagnostic DOM rendering,
- queue coordination status text and tone,
- privacy-safe incident status event dispatch.

`incident-reporter.js` continues to own state and workflow orchestration but delegates those DOM and event responsibilities to the new module.

## Privacy and data contracts

No audio, filenames, full paths, report text, stack traces, credentials, tokens, IP addresses, SSIDs, location data, or browser tab identifiers are added to diagnostics. Existing Firebase payloads, Firestore documents, SMTP content, DSP, mastering targets, encoders, and download formats are unchanged.
