# v1.6.14 Incident Callable Endpoint Diagnostics

## Goal

Separate Firebase Callable deployment, CSP/network reachability, and server-internal failures so the incident settings screen does not mislabel every generic Functions error as a network block.

## Changes

- Displays the exact callable function name: `getIncidentServiceStatus`.
- Displays the full regional Functions endpoint separately from the concise status message.
- Verifies the exact Functions origin against the Hosting CSP `connect-src` directive.
- On callable failure, performs a bounded privacy-safe direct HTTP probe with no credentials and an empty body.
- Classifies a 404 as likely function-not-deployed, a failed direct probe or missing CSP origin as network/CSP blocked, and a reachable `functions/internal` response as a server-internal error.
- Removes the old rule that converted a generic `functions/internal: internal` response into `FOXBEAR_INCIDENT_CALLABLE_NETWORK_BLOCKED` without reachability evidence.

## Privacy

The direct probe sends no audio, filename, local path, report payload, authentication credential, or user-entered content. It sends only an empty request to the known status function endpoint and is bounded by a 4.5-second timeout.

## Operations

After applying the patch, deploy the Hosting CSP and incident Functions from the same release:

```text
npm run deploy:incident
```

Then use `서버 연결 다시 확인` and confirm the UI separately reports callable name, endpoint, direct HTTP reachability, CSP status, and App Check mode.
