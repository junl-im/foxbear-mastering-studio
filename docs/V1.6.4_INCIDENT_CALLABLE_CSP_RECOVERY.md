# v1.6.4 Incident Callable CSP Recovery

## Problem

The web client initialized regional Firebase Callable Functions correctly, but the site Content Security Policy did not allow the regional Cloud Functions origin. Browsers could therefore reject `getIncidentServiceStatus`, `submitIncidentReport`, or `getIncidentDeliveryStatus` before the request reached Firebase.

## Fix

- Allow `https://asia-northeast3-foxbear-music.cloudfunctions.net` in both the HTML meta CSP and Firebase Hosting response CSP.
- Deploy Hosting, Firestore rules/indexes, and all incident Functions together through `npm run deploy:incident`.
- Return the canonical Callable origin from service metadata schema v2.
- Normalize blocked-network errors with endpoint and original error information.
- Show category-specific recovery guidance in the incident dialog.

## Deployment

Run `npm run deploy:incident` from the project root. The command now publishes the web CSP, Firestore security configuration, and the complete incident mail server stack together.
