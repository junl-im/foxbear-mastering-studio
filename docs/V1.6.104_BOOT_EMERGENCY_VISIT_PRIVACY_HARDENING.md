# v1.6.104 - Boot emergency upload and visit privacy hardening

## Problem

A critical initialization failure could activate the emergency file-input handler while the required first-entry UI-mode chooser still covered the application. If normal input binding partially completed before the failure, the fallback path could also attach a second `change` listener. Visit telemetry additionally preserved the full launch query before the PWA share-target service removed its temporary identifiers.

## Fix

- Add `releaseForEmergency()` to the UI-mode controller to clear required chooser state, shared overlay registration, app-shell inert state, and the body scroll lock.
- Publish the UI-mode controller before `init()` so partially initialized chooser state can still be unwound after an exception.
- Add an app-level DOM fallback so emergency upload remains reachable even when controller recovery itself is unavailable.
- Make emergency input binding idempotent with the normal `nativeInputChangeBound` contract.
- Record visit `page` and `path` from `location.pathname` only and defensively strip query/hash fragments in Firebase visit normalization.
