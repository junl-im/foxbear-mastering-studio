# v1.5.84 Trusted Types Browser Gate Recovery

## Incident

The browser release gate completed application startup and static serving, but ten visual tests failed while staging their synthetic UI. Chromium enforced the production `require-trusted-types-for 'script'` policy, so assigning plain strings to `Element.innerHTML` raised `TypeError: This document requires TrustedHTML assignment` before any layout assertion ran.

Affected specifications:

- `qa/browser/v1573-bulk-mastering-controls-visual.spec.js`
- `qa/browser/v1574-mobile-download-batch-controls-visual.spec.js`

## Fix

- Bulk mastering rows are built with `document.createElement`, `textContent`, style properties, and `list.replaceChildren(...rows)`.
- Download-sheet families, bitrate options, and action controls are built with structured DOM operations and appended without HTML parsing.
- `qa/no_html_injection_smoke.js` now audits `qa/browser` in addition to `src`.
- `qa/v1584_trusted_types_browser_qa_smoke.js` protects the two incident fixtures and their required construction contracts without requiring Playwright to be installed.

## Verification

Dependency-light static and regression verification completed at 295/295 PASS. The final incident confirmation is a rerun of the Playwright Chromium gate in CI.


Run the dependency-light regression checks:

```bash
node qa/no_html_injection_smoke.js
node qa/v1584_trusted_types_browser_qa_smoke.js
npm run check:static
```

Run the incident reproduction gate in an installed browser environment:

```bash
npm ci
npx --no-install playwright install --with-deps chromium
npm run qa:browser
```
