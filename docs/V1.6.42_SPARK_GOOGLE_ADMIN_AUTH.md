# v1.6.42 Spark Google Administrator Authentication

## Goal

Expose administrator monitoring from Settings without placing a password in the browser and without requiring the Blaze plan.

## Flow

1. The user opens `설정 → 관리자 모니터링`.
2. Firebase Authentication opens Google account selection with browser-session persistence.
3. The client reads only its own `siteAdmins/{UID}` document.
4. Firestore Rules require `google.com`, a verified email, `active: true`, and matching optional `email` and `authProvider` fields.
5. Authorized accounts open the existing visit and incident monitor. Unregistered accounts receive their UID for one-time console registration.
6. Administrator logout signs out Google and restores anonymous Firebase authentication.

## Spark deployment

```bash
firebase login
firebase use foxbear-music
npm run check:release
npm run deploy:spark
```

The Spark command deploys Hosting, Firestore Rules, and Firestore Indexes only.

## Administrator document

Document path: `siteAdmins/<Google Firebase UID>`

```text
active       Boolean  true
role         String   admin
email        String   mcwoogi@gmail.com
authProvider String   google.com
```

Clients may read only their own administrator document and cannot create, update, list, or delete administrator documents.

## Security notes

- No shared PIN exists in HTML, JavaScript, Functions, or release archives.
- Discovering the Settings button does not grant access.
- Authorization is enforced by Firestore Rules, not only by UI state.
- Google authentication uses browser-session persistence and explicit logout.
- Optional incident mail Functions remain a separate Blaze-only feature.
