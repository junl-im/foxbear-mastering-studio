# v1.6.112 Mastering Lifecycle Race Hardening

## Scope

This release closes four narrow lifecycle boundaries found during the v1.6.111 stability audit. It does not change the normal mastering DSP coefficients, loudness target, limiter target, pitch algorithm, or encoder math.

## Final output commit fence

`masterTrack()` now calls `assertMasteringJobActive('download-blob-validated')` immediately after asynchronous download-blob validation and before `URL.createObjectURL()` or any `track.out*` / `track.status = 'done'` commit. A delete/cancel arriving during validation therefore exits through the existing cancellation path instead of producing a ghost completion.

## Analysis-preflight cancellation

`waitForTrackAnalysisIfNeeded()` checks `isAnalysisCancellationError(error)` and `isTrackStillImported(track)` before incident reporting. Removed/cancelled tracks return `false` without being converted to an error. A still-imported track whose analysis was cancelled is normalized back to `ready` or `queued`.

## BFCache diagnostics recovery

Performance Diagnostics now binds lifecycle listeners once, stops the ambient timer on `pagehide`, and explicitly restarts it on `pageshow`, including a dedicated `ambient-health-bfcache-resume` reason for persisted BFCache restores.

## Finalizer fallback recovery

The rare Worker-failure path is extracted to `src/audio/master-finalizer-fallback-service.js`. Buffer cloning is chunked and yields on a bounded time budget, existing cooperative DC/sanitize helpers are reused, and cancellation/progress checkpoints are applied between the existing mobile-speaker, de-esser, multiband, loudness, gain, limiter, and final validation stages. Existing DSP functions remain authoritative.

## Regression

`qa/v16112_mastering_lifecycle_race_hardening_smoke.js` verifies fence ordering, cancellation-before-incident semantics, BFCache lifecycle hooks, fallback repeated yielding, sample-preserving recovery under neutral DSP mocks, and cancellation propagation.
