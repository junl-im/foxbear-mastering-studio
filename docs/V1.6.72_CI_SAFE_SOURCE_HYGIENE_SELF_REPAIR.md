# v1.6.72 CI-Safe Source Hygiene Self-Repair

## Problem

Extract-overwrite patches cannot delete files that already exist in a Git repository. If `.firebaserc`, `.firebase/hosting..cache`, or `qa/static-audit.txt` had previously been committed, the v1.6.71 normal GitHub Pages workflow used strict non-mutating validation and failed before dependency installation.

## Policy

The normal Pages release path now uses `FOXBEAR_SOURCE_HYGIENE_MODE=ci-safe`.

1. Remove only the fixed allowlist from the ephemeral Actions checkout.
2. Emit a GitHub warning annotation for each removed path.
3. Run the unchanged strict tracked-file hygiene check immediately afterward.
4. Fail for `.env*`, unknown unsafe artifacts, or anything outside the allowlist.

Explicit `FOXBEAR_SOURCE_HYGIENE_MODE=strict` remains available for non-mutating repository audits.

## CI allowlist

- `.firebaserc`
- `.firebase/`
- `.audit-results/`
- generated `dist/`
- generated QA text reports
- generated `PATCH_MANIFEST.json`

This allowlist does not include environment files, credentials, tokens, arbitrary logs, or unknown paths.

## Result

The exact three-path failure reported in GitHub Actions is converted from a blocking error into safe workspace cleanup followed by strict verification. Local cleanup and committing the deletions remain recommended, but missing that manual step no longer blocks the normal release gate.
