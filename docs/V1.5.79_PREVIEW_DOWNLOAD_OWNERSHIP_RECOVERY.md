# v1.5.79 Preview and Download Ownership Recovery

## Problem

A media element can be removed while its `play()` Promise or readiness wait is still pending. A late completion could start a fade or leave detached audio playing. The download assist also allowed repeated taps to launch overlapping native share/save operations, and Blob URL cleanup relied only on per-URL timers.

## Changes

- Each audio transition receives a monotonically increasing request ID.
- New play, pause, crossfade, or disposal invalidates older requests.
- Late completions return `false`; detached audio is paused and does not start a fade.
- Audio unregistering cancels pending playback before releasing visualizer and playback-link registrations.
- Share and direct-save actions use a panel-level single-flight lock with disabled and `aria-busy` states.
- Download URLs retain their state context in a central registry.
- Normal `pagehide` revokes all tracked URLs and timers, while persisted BFCache navigation keeps them alive.
