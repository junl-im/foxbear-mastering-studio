# v1.6.7 Incident Readiness, History Sync, and Performance Recovery HUD

## Purpose

This release reduces operational guesswork after Firebase deployment and makes automatic mail recovery visible without forcing another test message.

## Incident deployment readiness

The incident settings dialog provides one explicit self-check. The browser verifies that the canonical regional Callable origin is present in the active meta CSP. An authenticated Callable then verifies the deployed Functions version, Firestore Admin connectivity, Gmail app-password Secret format, and Gmail SMTP authentication/connectivity without sending an email.

## Live mail-test history

Pending and failed manual-test records are periodically refreshed from `getIncidentDeliveryStatus`. Scheduled retries therefore update the same bounded local history item with the latest status, SMTP attempt count, Message-ID, terminal state, and retry timestamps. The client stores no audio, filename, path, or mail body.

## Direct retry cooldown

The server serializes the last direct retry request and the next eligible time. The client displays a seconds countdown and keeps the direct retry control disabled until the server-defined cooldown expires. Server-side ownership, state, retry-count, and cooldown enforcement remain authoritative.

## Performance recovery HUD

The ambient health event includes confirmation sample counts. The mastering orchestrator retains the current measured health, warning codes, and recovery progress. During a performance-protection pause, the HUD displays the dominant reason or `정상화 확인 1/2`, and resumes only after stable normal health.
