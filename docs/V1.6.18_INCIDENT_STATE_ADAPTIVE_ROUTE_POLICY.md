# v1.6.18 Incident State Service and Adaptive Route Policy

## Scope

This release separates local incident UI persistence from reporting orchestration and reduces repeated latency when the direct Firebase Callable path is temporarily unreachable.

## State service

`src/boot/incident-state-service.js` owns:

- the latest five mail-test records;
- the latest deployment-readiness snapshot;
- the latest three deployment-check summaries;
- schema validation, date validation, bounds, and fail-closed corrupt JSON handling;
- privacy redaction before local persistence.

The main reporter keeps rendering and orchestration responsibilities and consumes the state service through `window.FoxBearIncidentState`.

## Adaptive route policy

`src/boot/incident-route-policy.js` stores metadata-only route health for `callable` and `hosting-rewrite`.

- The first transient failure is observed without changing order.
- A second consecutive transient Callable failure opens a two-minute cooldown.
- Additional transient failures extend the cooldown up to fifteen minutes.
- A successful Callable request resets the streak and closes the cooldown immediately.
- Permission, authentication, invalid request, missing Function, and SMTP configuration failures do not open the circuit.
- Firestore remains the final compatibility path and is not hidden by the route policy.

## Privacy

Route health stores only counters, timestamps, bounded error codes, and cooldown state. Mail-test and readiness state is normalized and redacted. No audio, filename, report body, full local path, token, or Secret is persisted by these modules.
