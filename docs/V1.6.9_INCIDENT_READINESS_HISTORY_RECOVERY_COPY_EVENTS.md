# v1.6.9 Incident Readiness History, Recovery Copy, and Status Events

## Scope

This patch makes deployment diagnostics easier to act on without increasing mail or SMTP traffic.

## Changes

- Stores only the latest three readiness summaries locally.
- Records check time, normal/failure state, failed stages, server version, and whether the result came from cache.
- Deduplicates results that share the same server check timestamp.
- Adds copy actions to failed CSP, Functions, Firestore, Gmail Secret, and SMTP cards.
- Uses `npm run deploy:incident` for deployable failures and a generic `FIREBASE_SETUP.md` reference for credential guidance.
- Never exposes Secret values or the server-only Secret identifier in the browser.
- Emits `foxbear:incident-status-change` after readiness and enabled-state changes.
- Updates the Settings summary immediately and preserves later rendering compatibility.

## Validation

Run `node qa/v1609_incident_readiness_history_recovery_copy_events_smoke.js` and `npm run check:static`.
