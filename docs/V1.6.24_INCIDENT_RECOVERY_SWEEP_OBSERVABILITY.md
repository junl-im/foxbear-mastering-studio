# v1.6.24 Incident Recovery Sweep Module Split and Observability

## Scope

- Split lifecycle-triggered incident recovery orchestration out of the large `incident-reporter.js` boot module.
- Preserve coalescing across online, long-resume, and connection-change triggers.
- Record offline recovery attempts as first-class diagnostic snapshots.
- Surface contained lifecycle callback failures through reporter status and copied diagnostics.

## Confirmed problems

1. The recovery sweep implementation lived inside the 100 KB+ reporter module, coupling queue, history, service, deployment, lifecycle, UI, and diagnostics responsibilities.
2. An offline sweep returned a result to the caller but did not update `lastLifecycleSweepAt` or `lastLifecycleSweepResult`, so settings and copied diagnostics could show the previous online result.
3. The lifecycle service contained rejected callbacks, but the reporter did not provide an `onError` observer. Contained failures therefore disappeared from operational diagnostics.
4. Sweep phase errors could repeat the same normalized code across queue/history/service/deployment phases without a bounded deduplicated summary.

## Changes

- Added `src/boot/incident-recovery-sweep-service.js` with a reusable controller that owns request merging, single-flight execution, pending sweep coalescing, phase isolation, bounded error summaries, result snapshots, state inspection, and disposal.
- The reporter now supplies queue, history, service, and deployment callbacks to the controller instead of owning the orchestration loop.
- Every sweep result, including offline results, updates reporter state and emits an incident status event.
- Lifecycle callback failures now update `lastLifecycleError` and appear in `getStatus()` and copied anonymous diagnostics.
- Lifecycle callbacks return the sweep Promise to the lifecycle service rather than pre-emptively swallowing rejections.

## Compatibility

- Incident payloads, Firestore schema, Functions, SMTP, audio DSP, mastering targets, encoders, and download formats are unchanged.
- Coalescing remains last-six-reasons bounded and OR-merges force-service and deployment-check requirements.
- Network phases are skipped while offline, but local queue/history counts are still included in the diagnostic result.
- Existing reporter public methods remain available.

## Verification

- New deterministic module regression covers in-flight coalescing, pending reason merging, forced service/deployment phases, offline snapshots, bounded duplicate error summaries, observer callbacks, predicate fallbacks, count callback failures, and disposal.
- Historical incident reporter VM tests load the extracted service before the reporter.
- `npm run check:static`: 357/357 passed.
- Browser fixture preflight, Functions syntax, release metadata, handoff state, SRI, and dependency metadata checks passed.
- Dependency health reported five expected installation warnings because Playwright and Functions runtime dependencies are not installed in the sandbox.
- Installed Chromium execution, production Firebase/App Check/Gmail, and real-device long-background behavior remain environment gates.
