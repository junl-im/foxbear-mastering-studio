# v1.6.110 UI Mode Early Boot Recovery

## Problem

The first-entry chooser was visible from static HTML, but its AI/Expert click handlers were only attached when `app.js` reached `initUiModeExperience()`. Any bootstrap delay or failure before that point could leave a visually healthy but non-interactive required chooser blocking the workspace.

## Fix

`ui-mode-service.js` now installs a capture-phase early choice bridge immediately when the head script loads. If the normal controller exists, the bridge delegates to it. Otherwise it persists a pending mode, updates the body/prepaint mode, hides the chooser, clears the required state, releases `.app-shell` inert state, and emits a diagnostic event. Later normal initialization adopts the pending/session mode.

## Safety

No mastering DSP, audio analysis, export, Firebase, or Service Worker algorithms are changed by this hotfix.
