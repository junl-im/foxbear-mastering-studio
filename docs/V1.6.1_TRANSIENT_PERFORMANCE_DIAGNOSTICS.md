# v1.6.1 Transient Performance Diagnostics

## Problem

Opening memory/performance diagnostics from Settings called the same persistence path used by historical debugging builds. That stored `foxbear-perf-diagnostics=on`, so subsequent normal launches automatically opened the panel even when the user did not request it.

## Changes

- Normal startup ignores and clears the historical persisted `on` value.
- Settings and keyboard openings are session-only.
- Automatic opening remains available only through explicit `?perf=1` or `?foxbearPerf=1` URLs.
- Automatically opened diagnostics wait for runtime health and app readiness, then close after two consecutive healthy samples and at least 3.5 seconds of uptime.
- Pointer interaction converts the current panel to manual mode so it does not disappear while being inspected.
- Lifecycle state is exposed for regression and support diagnostics.

## Regression

Run `node qa/v1601_transient_performance_diagnostics_smoke.js`.
