# v1.6.35 History Terminal Race and Service-Worker Activation Lease

## Audit scope

- Overlay terminal recovery boundary immediately before or after a delayed `popstate`.
- Non-BFCache page unload while an internal overlay history release is active.
- Multiple tabs attempting to send `SKIP_WAITING` for the same waiting service worker.
- Controller-change timeout recovery, BFCache activity lifecycle, download Object URL ownership, and managed AudioContext cleanup.

## Problems found

1. Terminal history recovery forgot its generation immediately. A delayed internal `popstate` queued near the 30-second boundary could therefore pass through as a genuine Back event and reach the workspace exit guard.
2. A non-BFCache `pagehide` suspended the internal release like BFCache even though the page would not be restored, leaving avoidable state behind during teardown.
3. Each idle tab could independently send `SKIP_WAITING`; successful `postMessage` without a later `controllerchange` also left activation permanently pending.
4. Replacing the download assist with the same Object URL revoked the URL that the new panel still needed.

## Changes

- Keeps a terminally recovered generation for a bounded 500 ms boundary grace and absorbs only that exact late destination generation.
- Resets history release state immediately on non-persisted page unload.
- Adds a verified localStorage activation lease so one tab owns `SKIP_WAITING` at a time.
- Adds a 12-second activation watchdog that releases ownership and resumes checks if `controllerchange` never arrives.
- Releases the lease on controller change and detects peer lease replacement through storage events.
- Preserves a reused download Object URL when replacing the assist panel.
- Adds 200-cycle managed AudioContext creation and close stress coverage.
