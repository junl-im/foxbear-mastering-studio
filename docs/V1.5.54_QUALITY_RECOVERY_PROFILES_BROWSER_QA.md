# FoxBear v1.5.54 Quality Recovery Profiles and Browser QA

## Scope

v1.5.54 continues the v1.5.53 one-shot engine recovery patch. The previous release used one generic conservative settings plan for every quality-gate failure. This patch maps failed audit signals to deterministic recovery profiles and adds real-browser success and exception-preservation scenarios.

## Recovery profiles

- `integrity-reset`: invalid/NaN/Infinity output samples; strongest DSP and headroom reduction.
- `loudness-relief`: dynamic collapse, clipping, limiter, Short-term LUFS, or loudness pressure.
- `low-end-control`: low-frequency pumping and sustained limiter activity.
- `phase-stabilization`: stereo phase and mono-compatibility risk.
- `spectral-preservation`: high-frequency loss, De-esser, or multiband over-processing.
- `translation-balance`: mobile/phone-speaker translation over-correction.
- `balanced-safety`: compatibility fallback when a failed item has no recognized code or label.

When several failures occur, all matched safety modifiers are applied. The highest-priority match becomes the visible primary profile. Retry count remains one.

## Diagnostics

`FoxBearMasteringDiagnostics.getSnapshot()` now reports the recovery profile ID/label, risk codes, recovery error, first-render preservation state, output byte size, output format, and existing DSP timing data.

The quality-gate panel displays the selected recovery profile for running, recovered, failed-after-retry, and exception states.

## Browser QA contract

The browser scenario decodes and masters a real synthetic WAV. E2E injection changes only the quality decision and optional exception point:

1. Inject `PHASE_RISK`; confirm `phase-stabilization` performs one safe rerender and produces output.
2. Inject `HIGH_LOSS` and throw after the recovery render; confirm the original encoded output still completes, remains non-empty, and diagnostics record `preservedFirstRender: true`.

The hook is ignored unless `window.__FOXBEAR_E2E__ === true`.

## Remaining considerations

- Profile thresholds are deterministic safety defaults, not genre-specific mastering advice.
- Real-device listening tests should compare recovery profiles against the first render before further aggressive tuning.
- Browser QA should run on both desktop Chromium and the mobile PWA project before release.
