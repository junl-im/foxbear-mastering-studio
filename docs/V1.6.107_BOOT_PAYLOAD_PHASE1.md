# v1.6.107 Boot Payload Phase 1

## Goal

Reduce first-load and post-boot contention without changing mastering DSP or the visible workspace contract.

## Changes

- Service Worker warming is scheduled through an idle window instead of being posted immediately after `serviceWorker.ready`.
- Warming is suppressed on offline, Save-Data, slow-2G/2G, hidden-page, or active audio/export states and retries only a bounded number of times.
- Background warm concurrency is capped at three and path-equivalent versioned/unversioned entries are deduplicated.
- `admin-incident-monitor.css` is no longer render-blocking and is excluded from the SW warm graph. It is loaded with SRI only after administrator access is verified so Visits UI is styled before use; the heavier incident-monitor JS remains lazy until the incident tab is opened.
- Filename summary and Detail rendering tolerate missing optional modules so Queue/Dock/core status rendering can continue.

## Measured impact

- Initial render-blocking stylesheets: **26 → 25**, **-20,161 bytes** uncompressed.
- Service Worker warm graph: **156 → 146** entries, **-141,709 bytes** uncompressed.
- Canonical warm-path duplicates: **9 → 0**.
- Warm concurrency: **6 → 3**.
- Initial script count remains **92** in phase 1; JavaScript graph reduction is reserved for phase 2.

## Verification

- Configured static/behavioral QA: **463/463 PASS** using the same QA runner in three sequential slices to stay within the review-container wall-time.
- Version/SRI, Source Hygiene, Browser preflight, Functions syntax, Firebase Hosting boundary **162 files**: **PASS**.
- Full Playwright execution is not available in this container because `@playwright/test` is not installed; GitHub Actions remains the browser-runtime gate after push.

## Non-goals

- No mastering DSP, analysis, limiter, loudness, encoder, or download pipeline changes.
- Bulk HUD and download-dialog JavaScript remain eager in this phase; they are candidates for the next payload phase after browser verification.
