# v1.6.113 Incident Server Boundary and Finalizer Parity Hardening

## Incident security boundary

`incidentReports` client create is denied by Firestore Rules. The browser submits through `submitIncidentReport` using Firebase Callable first and the Hosting same-origin rewrite as the network recovery route. If both server routes fail, the report remains in the existing local recovery flow instead of writing Firestore directly. This keeps UID/global admission buckets authoritative.

## Finalizer recovery parity

The main-thread finalizer recovery path now uses the same positive loudness gain limits as the Worker path: max +9 dB, balanced +7 dB, fast +5 dB. Main-thread limiter telemetry now exposes active percentage, mean reduction, and normalized gain movement so Quality Gate pumping checks remain available after Worker recovery. Sample-peak mode reports 1x oversampling while true-peak mode reports 4x.

## Regression coverage

`qa/p1_incident_finalizer_hardening_smoke.js` protects the server-only Firestore boundary and dynamically verifies fallback gain/oversample/limiter telemetry. Historical regression tests that encoded the retired direct Firestore fallback have been migrated to the server-only contract.

Configured static/regression target: 470 checks.
