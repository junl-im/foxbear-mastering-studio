# v1.6.68 Public Shell Cache Integrity and SRI Coverage

## Problem

Firebase Hosting serves `/src/**`, `/assets/**`, and `/vendor/**` with a one-year immutable cache policy. The main `index.html` used the current release query, but `external-browser.html` loaded local CSS, JavaScript, and icons without that generation query, while `design-preview.html` retained a historical v1.3.20 query. A previously cached public shell could therefore continue requesting an old immutable resource after a new deployment.

The SRI updater covered `index.html` and `external-browser.html`, but the general verifier checked only `index.html`, and `design-preview.html` was outside both automated paths.

## Change

- Synchronize release metadata in all three deployed public HTML shells.
- Require the current `assetVersion` on local script, stylesheet, manifest, and image references.
- Update and validate SHA-384 SRI for local JavaScript and CSS in all three shells.
- Add explicit no-cache/no-store Hosting headers to public root recovery and metadata documents.
- Route allowlisted auxiliary HTML through a dedicated network-first service-worker path while preserving query parameters and a canonical offline fallback.
- Version PWA manifest icons and auxiliary cache entries with the same release generation.
- Treat generated `dist/` output as locally repairable so Hosting checks do not block later delivery packaging in archive-mode workspaces.
- Add a dedicated static regression contract.

## Risk control

No audio engine, mastering pipeline, export codec, Firestore schema, or Callable behavior changes are included.
