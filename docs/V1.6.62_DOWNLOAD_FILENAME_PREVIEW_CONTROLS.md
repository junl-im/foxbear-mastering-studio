# v1.6.62 Download Filename Preview, Metadata Controls, and Collision Preflight

## User goal

Make human-readable filenames controllable and predictable before a download begins, while keeping bulk exports safe and the interface stable on desktop, mobile, and embedded browsers.

## Root causes found

1. v1.6.61 produced readable names but exposed no preference controls.
2. The user could not see the final filename until the browser save operation started.
3. Some paths trusted `track.outName`, so a preference change could be ignored by same-format or bulk downloads.
4. Existing masters could be mislabeled if a later UI style/platform setting was consulted instead of the values used at mastering time.
5. Duplicate ZIP names were corrected internally but not surfaced before the export.
6. localStorage failure could make controls appear changed while later naming silently returned to defaults.
7. A CSS `:has()` selected-state rule was unnecessarily risky for older or embedded browser engines.
8. Long multilingual titles and a two-column settings grid required explicit narrow-screen containment.

## Implemented design

### Immutable mastering metadata

At successful mastering completion, `track.outputNameMeta` captures and freezes target LUFS, mastering style, platform, output format, and extension. Existing outputs use this captured record even when the user later changes current mastering controls.

### One global preference model

`FoxBearFileNamePolicyService` owns five booleans:

- `includeMastered`
- `includeLoudness`
- `includeStyle`
- `includeFormat`
- `includePlatform`

Preferences are stored in localStorage when available. The service also retains an in-memory copy so blocked/private/embedded storage does not create a misleading control state during the current session.

### Exact live preview

The download dialog computes the same policy result used by the real download. Switching WAV/MP3 quality updates the quality token and extension immediately. The preview wraps rather than widening the modal and exposes the full value through the title attribute.

### Export collision preflight

The main export area prepares the same deterministic ZIP name plan used by export and reports the number of names adjusted because of duplicates. Identical entries resolve as `Title ... (2).wav`, `Title ... (3).wav`.

### Workflow extraction and offline readiness

Filename composition, completed-output refresh, and bulk-summary rendering were extracted into `src/download/file-name-workflow-service.js`. This keeps `src/app.js` below the established architecture line budget and makes the workflow independently testable. The new module is loaded with SRI and included in the service-worker current cache so offline startup cannot lose the naming workflow.

### Responsive and compatibility polish

- Long filename text uses `overflow-wrap: anywhere` and constrained width.
- Filename controls collapse from two columns to one below 420 px.
- Head actions stack on narrow screens.
- Checkbox selected state uses an explicit `.is-checked` class rather than CSS `:has()`.
- Controls disable while conversion is active, preventing preference/preview drift during an in-flight operation.

## Exception and challenge audit

1. **All metadata enabled?** Full readable suffix is generated.
2. **One token disabled?** Only that token disappears; spacing stays normalized.
3. **Every token disabled?** A valid title plus extension remains.
4. **Platform absent/custom?** No empty or meaningless platform token is appended.
5. **Format changed in dialog?** Preview extension and quality token update together.
6. **Current style changed after mastering?** Captured original style remains.
7. **Current platform changed after mastering?** Captured original platform remains.
8. **Same-format direct save?** Name is rebuilt from current preferences.
9. **Alternate-format save?** Same policy applies with the selected variant format.
10. **Share flow?** Shared file receives the same rebuilt name.
11. **Sequential save?** Every entry uses the same policy.
12. **ZIP export?** Planning and worker receive the same final names.
13. **Duplicate title?** Stable ` (2)`, ` (3)` suffixes are assigned.
14. **Case-only duplicate?** Collision comparison remains case-insensitive.
15. **Forbidden filesystem characters?** They become normalized spaces.
16. **Directional-control characters?** They are removed to prevent deceptive display.
17. **Windows reserved title?** Reserved-name protection remains active.
18. **Trailing period/space?** Unsafe trailing characters are removed.
19. **Very long Korean title?** UTF-8 byte truncation preserves the suffix and extension.
20. **Emoji family sequence?** Safe joiner-based emoji remains intact.
21. **Old underscore output reimported?** Humanization and generated-suffix cleanup remain active.
22. **Partial old suffix reimported?** `15LUFS wav24`-style tails do not duplicate.
23. **Storage unavailable?** Current-session preference memory remains authoritative.
24. **Storage reset unavailable?** Reset clears the in-memory fallback and returns defaults.
25. **Rapid preference clicks?** Preview and completed-output names refresh from one normalized state.
26. **Conversion already running?** Controls are disabled until operation settlement.
27. **Long preview on desktop?** It wraps inside the card without modal expansion.
28. **420 px phone width?** Options become a single column.
29. **Old embedded CSS engine?** Required selected styling does not rely on `:has()`.
30. **No completed tracks?** Bulk filename summary stays hidden.
31. **Completed-track count changes?** Summary key invalidates and collision plan refreshes.
32. **Preference bits change?** Summary key invalidates even with the same tracks.
33. **Master invalidated/remastered?** Frozen metadata is cleared and replaced by the new run.
34. **Filename-only preference changes?** Audio Blob/cache content remains untouched.
35. **Policy service unavailable/error?** Existing safe fallback name remains available.
36. **Browser visual automation unavailable?** Static layout contract and browser preflight remain mandatory, with real-device acceptance recorded separately.

## Known ambiguity

A title that legitimately ends with text identical to FoxBear-generated metadata, such as `Song 15LUFS wav24`, may be interpreted as a prior generated suffix during reimport cleanup. This is intentionally conservative to prevent repeated metadata. A future release can preserve a dedicated original-title field or embedded metadata to eliminate this ambiguity completely.
