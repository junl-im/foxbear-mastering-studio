# v1.6.85 Browser Sentinel UI Mode / Header Recovery

## Goal

Recover the persistent two-case browser release failure after the v1.6.80 workspace selector while preserving the required first-entry product experience and the v1.6.81 mobile touch target.

## Root-cause boundaries

- Browser QA uses Runtime Health as a sentinel; when it fails, heavier browser scenarios are skipped.
- The E2E workspace fixture previously relied on `sessionStorage` as its only durable handoff into the pre-paint UI-mode service. The product now also accepts the already-scoped `__FOXBEAR_E2E_UI_MODE__` global when `__FOXBEAR_E2E__ === true`, so storage restrictions cannot reopen the required chooser over browser QA.
- The v1.6.80 header gained the workspace switch, but the older compact-header contract still expected the studio token to remain visible through 393px and capped the row at 38px. The v1.6.81 mode switch intentionally uses a 40px mobile target. On 393px-class layouts that combination clips the left command group.

## Patch

- Preserve the 40px workspace mode touch target.
- Hide the redundant `AI MUSIC MASTERING STUDIO` command token at 430px and below, leaving build/device identity visible without horizontal clipping.
- Update Runtime Health to measure the workspace switch explicitly, ignore responsive-hidden elements in centerline calculations, and accept the intentional 40px compact row within a 42px bound.
- Verify the requested E2E mode after navigation instead of silently continuing when pre-paint mode establishment failed.
- Emit one GitHub error annotation per repeated browser case, including project, spec, title, and bounded retry error text.

## Source hygiene

`PATCH_MANIFEST.json` remains a delete-path-only legacy artifact. Apply the cleanup helper and commit its deletion; CI auto-repair remains non-blocking but should no longer be needed after the repository deletion is committed.
