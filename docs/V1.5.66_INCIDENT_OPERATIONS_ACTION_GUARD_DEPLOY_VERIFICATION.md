# v1.5.66 Incident Operations Action Guard and Deployment Verification

## 목표

v1.5.66은 관리자 운영 작업의 중복·남용을 서버에서 차단하고, 보조 경보 채널 테스트, 운영 이력 상세 조회, 장애별 권장 조치, 배포 후 자동 상태 검증을 추가합니다.

## 변경 내용

- 단일 재전송, 일괄 복구, 보조 경보 테스트, 배포 검증에 Firestore 트랜잭션 기반 실행 임대와 쿨다운을 적용합니다.
- 동일 관리자 요청이 실행 중이면 `already-running`, 쿨다운 중이면 `cooldown`과 재시도 가능 초를 반환합니다.
- 관리자 화면에서 보조 HTTPS 웹훅을 실제 테스트하고 제공자·HTTP 상태를 확인할 수 있습니다.
- `incidentOperationsHistory`에 원인 코드와 권장 조치를 저장하고 최근 24시간 상세 이력을 표시합니다.
- 화면 릴리스와 Functions 릴리스가 다르거나 배포 검증이 24시간 이상 오래되면 관리자 화면이 자동 검증 요청을 생성합니다.
- 배포 검증은 SMTP Secret/인증, 웹훅 설정, 일괄 복구·경보 테스트·요청 제한·이력 기능의 서버 기능 세대를 기록합니다.

## 배포 후 자동 상태 검증

관리자 오류 관리 화면을 열면 `incidentOperations/deployment` 문서가 없거나 오래됐거나 화면 버전과 Functions 버전이 다를 때 한 번 자동 검증합니다. 자동 검증도 서버 쿨다운을 적용하므로 새로고침 반복으로 SMTP 인증 점검이 남용되지 않습니다.

## 배포 대상

- Firestore Rules
- `testIncidentAlertChannelRequest`
- `verifyIncidentDeploymentRequest`
- 기존 Incident Functions 전체
- Hosting 정적 자산

## 제한 사항

- 실제 Gmail SMTP 인증과 웹훅 수신은 배포된 Firebase 환경에서만 최종 확인할 수 있습니다.
- 웹훅 테스트는 실제 외부 메시지 1건을 생성하므로 5분 쿨다운을 적용합니다.
