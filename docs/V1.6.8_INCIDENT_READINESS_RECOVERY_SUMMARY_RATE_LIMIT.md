# v1.6.8 Incident Readiness Recovery Summary and Rate Limit

## Scope

This patch reduces repeated deployment diagnostics and makes the recovery path visible without forcing users to interpret raw Firebase errors.

## Behavior

- Client and server both enforce a 60-second readiness-check cooldown.
- Repeated checks during the cooldown reuse the previous result and do not reconnect to Gmail SMTP.
- The most recent healthy timestamp is preserved if a later check fails.
- Each readiness card includes a concise recovery location or deploy action.
- Firebase Secret values and identifiers remain server-side and are not exposed in the web UI.
- Settings shows a compact incident-mail health summary.
- Narrow screens use single-column readiness cards, 42px action targets, and contained modal scrolling.
