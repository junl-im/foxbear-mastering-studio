# v1.5.89 Browser Health-First Gate, Selector Impact, and Flaky Issue Reporting

## Summary

This patch makes the Browser release gate fail faster and select tests more precisely without weakening conservative fallbacks. Runtime Health is now a mandatory sentinel before expensive browser scenarios. Shared CSS changes can be mapped from selector tokens found near the Git diff, while missing or unknown selector evidence still runs the complete suite.

## Health-first execution

- `npm run qa:browser` runs `qa/browser/runtime-health-playwright.spec.js` first.
- A sentinel failure exits immediately and does not start visual, bulk, playback, quality, or PWA scenarios.
- A sentinel pass continues with the remaining impact-selected or complete spec set.
- `npm run qa:browser:retry` remains a direct `--last-failed` run and does not split the stored failed cases.
- Browser preflight runs once in the health-first wrapper and child phases receive the validated-preflight marker.

## Impact mapping

New direct mappings cover:

- Runtime Health and performance diagnostics.
- Service worker update, recovery, update safety, and session handoff.
- Admin incident operations UI and reporting.
- Quality report, mastering inspector, reference profile, and comparison waveform paths.

For shared CSS files, changed selector tokens are extracted from the Git diff. Known selectors select their related specs. Missing selector evidence or an unmapped selector promotes the run to the complete suite.

## Flaky issue report

The cumulative flaky ledger now also writes `qa/browser-results/flaky-issue-report.md`. The report places unresolved repeated or missing outcomes before recurring retry recoveries and includes an investigation checklist suitable for a GitHub issue body.
