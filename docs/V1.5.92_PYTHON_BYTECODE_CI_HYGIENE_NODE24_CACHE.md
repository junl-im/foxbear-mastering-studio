# v1.5.92 Python Bytecode CI Hygiene and Node 24 Cache Actions

## Problem

The GitHub static release gate could fail when a stale `qa/__pycache__` or `tools/__pycache__` directory already existed before the v1.5.90 hygiene assertion ran. The QA runner also relied on individual Python commands carrying `-B`, so a newly added indirect Python invocation could reintroduce bytecode. Browser workflows additionally used `actions/cache@v4`, which emitted the GitHub-hosted Node 20 deprecation warning.

## Changes

- Added `qa/python-bytecode-hygiene.js` to find and remove repository Python bytecode safely.
- The complete QA runner now removes stale bytecode before checks, after every check, and during final cleanup.
- All QA child commands inherit `PYTHONDONTWRITEBYTECODE=1`.
- The isolated SRI repair subprocess now also launches Python with `-B`.
- GitHub cache, restore, and save actions were upgraded to `actions/cache@v5`.
- Added a behavioral regression that seeds stale caches and imports a Python module through the shared QA runner.

## Verification

- Seeded `qa/__pycache__` and `tools/__pycache__` are removed before the historical v1.5.90 assertion.
- A child `python3 -c "import probe"` invocation leaves no `.pyc` or `__pycache__` output.
- Both Pages workflows contain no `actions/cache@v4` references.
- Static and packaging gates remain dependency-light and archive hygiene remains unchanged.
