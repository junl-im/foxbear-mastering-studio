# v1.6.80 AI Mastering / Expert Workspace

## Goal

Introduce a first-entry workspace choice without forking the mastering application state or audio pipeline.

- **AI 마스터링**: mobile-first single-column workspace showing only import, work queue, and analysis in the main canvas.
- **전문가 모드**: the existing full studio layout with presets, DSP controls, engine options, and professional tools.

Both modes reuse the same track objects, analysis results, mastering jobs, download artifacts, playback state, Dock, workers, and Firebase/runtime services.

## Interaction contract

- A required mode chooser appears on the first full visit of a browsing session.
- The chosen mode is stored in `sessionStorage`; reloads in the same tab keep the current workspace without repeatedly blocking the user.
- The header **작업 방식** control can reopen the chooser at any time.
- Switching modes must not clear the queue, rerun analysis, invalidate masters, stop Dock playback, or recreate audio state.
- The initial chooser cannot be dismissed with Escape or backdrop click until a mode is selected.
- When AI mode is selected, focus returns to **파일열기** for a direct mobile workflow.

## AI workspace layout

The same DOM is reused and restyled with `body[data-ui-mode="ai"]`:

1. 불러오기 — 파일열기 / 폴더열기 remain side by side.
2. 작업 대기열 — existing track cards, per-track mastering, download, retry/delete actions and progress remain intact.
3. 분석 — existing analysis/detail panel remains intact.
4. Dock — unchanged and shared with Expert mode.

The expert-only control zones and the large engine/action panel are hidden only at the presentation layer. They remain initialized so a mode switch restores the full studio instantly.

## Safety notes

- No duplicated track list, analysis view, player, or mastering controls are created.
- No separate AI-mode state store exists.
- Mode switching only changes a body data attribute and focus/layout synchronization.
- Existing mastering/navigation/BFCache/Service Worker logic remains shared.
