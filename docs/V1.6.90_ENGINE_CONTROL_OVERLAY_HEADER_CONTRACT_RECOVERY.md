# v1.6.90 Engine control overlay isolation + header contract recovery

## Problem

Two independent mobile failures were still unresolved after v1.6.89:

1. GitHub Actions continued to report the `chromium-mobile-pwa` Runtime Health header collision at `rowOverlap=91.96875px`, even though the current stylesheet already contained the final two-rail Flex ownership rule.
2. The Mastering Engine controls (`masterGoalSelect`, `masterStyleSelect`, `masterStrengthSelect`, `platformPresetSelect`) could make the mobile PWA appear frozen after opening/selecting an option.

A user performance snapshot from the affected UI showed no runtime faults and no active mastering/worker/audio work, while an overlay-history sentinel remained active. That points first to the UI overlay/history ownership path rather than to DSP computation.

## Recovery

### Engine control UI

- Engine/action select popups opt out of browser-history ownership with `history:false`.
- They opt out of modal-controller body locking with `lockScroll:false`.
- The popup closes before its native `change` event is dispatched.
- The change event is deferred by one animation frame so the overlay can visually release before synchronous state handlers run.
- Master goal/style/strength/platform render updates use `FoxBearRenderScheduler` instead of direct full `renderAll()` calls.
- Touch behavior changes from blanket `touch-action:none` to tap-safe backdrop handling plus `pan-y` on the option list.
- `window.FoxBearEngineControlDiagnostics` records popup opens/closes, selections, pending dispatches, and dispatch duration. Performance diagnostics now include this snapshot and can flag a body lock or a stuck pending dispatch.

### Browser header gate

- `header-command-bar.css` publishes `--foxbear-header-contract: flex-two-rail-v1690`.
- Runtime Health checks that exact marker at Pixel-class and 320px widths before accepting geometry.
- Initial failure diagnostics also include the computed top-level display and left/right flex ownership values.

This distinguishes a true geometry regression from a stale/missing stylesheet generation without weakening `rowOverlap <= 1px`.
