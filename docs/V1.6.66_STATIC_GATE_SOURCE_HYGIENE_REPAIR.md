# v1.6.66 Static Gate Source Hygiene Repair

## 문제

v1.6.65부터 정적 릴리스 게이트는 `.firebaserc`, `.firebase/`, `qa/static-audit.txt` 같은 로컬·생성 파일이 Git에 남아 있으면 실패한다. ZIP 덮어쓰기는 기존 파일을 삭제할 수 없기 때문에 `DELETE_PATHS.txt`의 수동 삭제가 누락되면 GitHub Actions가 즉시 중단될 수 있었다.

## 적용

- `tools/repair-source-hygiene.js`가 삭제 가능한 로컬·생성 경로만 제한적으로 정리한다.
- 정적 및 전체 릴리스 게이트와 `package:delivery`는 정리 후 기존 엄격한 `source:hygiene` 검사를 다시 실행한다.
- `.env`, 비밀 키, 기타 secret-like 파일은 자동 삭제 대상이 아니며 계속 게이트를 실패시킨다.
- Windows/GitHub Desktop 사용자는 저장소 터미널에서 `npm run source:hygiene:repair`를 실행해 실제 삭제 변경을 표시할 수 있다.
- macOS/Linux 사용자는 `APPLY_PATCH_CLEANUP.sh` 또는 동일한 npm 명령을 사용할 수 있다.

## CI 동작

GitHub Actions 작업 공간에 과거 생성 파일이 남아 있으면 자동 정리 후 검사를 계속한다. CI 로그에는 저장소에서도 해당 삭제를 커밋하라는 경고가 표시된다. 릴리스 ZIP과 Hosting payload에는 기존과 동일하게 금지 파일이 포함되지 않는다.

## 검증

전용 회귀는 다음을 확인한다.

1. Git에 추적된 `.firebaserc`, `.firebase/hosting..cache`, `qa/static-audit.txt`가 안전하게 제거된다.
2. 정리 후 `check-source-hygiene.js`가 통과한다.
3. `.env.production` 같은 비밀 환경 파일은 자동 삭제되지 않고 검사에서 계속 실패한다.
4. 정적 릴리스 게이트가 `source:hygiene:repair` 다음에 `source:hygiene`을 실행한다.
