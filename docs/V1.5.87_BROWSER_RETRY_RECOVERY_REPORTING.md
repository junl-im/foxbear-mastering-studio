# v1.5.87 Browser Retry Recovery Reporting

## 문제

failed-only 재실행이 성공하면 Browser release gate는 통과할 수 있었지만, 최초 실패가 실제 flaky였는지, 같은 테스트가 다시 실패했는지, 재실행 결과에서 누락됐는지를 즉시 구분할 수 없었다. 또한 fixture 계약 검사는 대량 마스터링 HUD와 다운로드 시트만 다뤄 Runtime Health 헤더와 PWA 복구 경로의 구조 변경을 브라우저 실행 전에 잡지 못했다.

## 변경

- `qa/browser/retry-recovery-report.js`가 primary JSON과 failed-only retry JSON을 안정적인 spec/title/project 키로 비교한다.
- 회복된 flaky, 반복 실패, 재실행 결과 누락을 JSON과 Markdown으로 각각 기록한다.
- GitHub Actions Job Summary에 재실행 결과 표를 추가하고 flaky 회복은 warning annotation으로 표시한다.
- 결과 보고 단계는 Playwright 성공/실패 상태를 덮어쓰지 않으며 원본 artifact와 함께 보존된다.
- fixture preflight 범위를 Runtime Health 릴리스 헤더와 PWA wake-lock/service-worker 복구 계약까지 확대한다.

## 검증

- synthetic primary/retry 보고서에서 회복 1건, 반복 실패 1건, 누락 1건을 정확히 분류한다.
- JSON, Markdown, GitHub summary 파일 생성을 임시 파일 시스템에서 검증한다.
- 현재 production Runtime Health/PWA 계약이 모두 통과하며 누락 시 Chromium 이전에 실패한다.
