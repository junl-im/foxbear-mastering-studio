# v1.6.5 Incident Mail Recovery, History, and SMTP Diagnostics

## User-facing recovery

The incident settings dialog now includes a server connection recheck and a copy action for `npm run deploy:incident`. These controls keep the recovery path inside the product instead of relying on users to discover deployment instructions elsewhere.

## Recent test history

The latest five manual mail-test results are stored in localStorage. Entries contain only time, normalized result, a bounded summary, report ID, and Message-ID. Audio, filenames, local paths, and message bodies are not stored. Users can clear the list at any time.

## SMTP failure normalization

The Functions delivery path now keeps a normalized reason separate from the raw provider code. The web UI distinguishes invalid Secret configuration, Gmail authentication rejection, recipient rejection, quota or rate limiting, and SMTP network failure. A next retry timestamp is exposed when available.

## Service metadata

Incident service schema v3 reports the Gmail provider and the Firebase Secret credential mode without exposing any secret value.

## Verification

Run `node qa/v1605_incident_mail_recovery_history_smoke.js`, then `npm run check:static`, `npm run functions:check`, and `npm run check:release`.
