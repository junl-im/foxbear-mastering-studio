# v1.6.33 Full Audit and Overlay History Watchdog Recovery

## Audit scope

- System: boot order, service-worker cache generation, release metadata, SRI, PWA navigation guards, Firebase Functions syntax, handoff and archive contracts.
- Performance: synthetic mastering throughput, golden-audio loudness/peak contracts, timer and pending-generation bounds, Worker and object-URL lifecycle regressions.
- Technology: browser History API, BFCache, modal layering, service-worker precache, dependency metadata, cross-tab incident coordination.
- Functionality: dialog open/close, browser Back, normal close, delayed or omitted popstate, download/recommendation/settings/incident overlays.
- Engine: analysis, mastering, loudness measurement, true-peak protection, encoding and cancellation regression coverage.
- Errors and exceptions: omitted popstate, delayed generation, stalled traversal, metadata mismatch, missing installed browser/runtime dependencies.

## Problems found

1. A browser could complete the internal `history.back()` traversal but omit its `popstate`. The destination state was already the expected base generation, yet the controller only marked the transaction stalled. `historyReleaseInFlight` then remained active and could block a fresh sentinel for a later dialog.
2. Short-lived delayed release generations were time-bounded but not count-bounded. A burst of navigation mismatches could grow the pending-generation map until its 30-second TTL elapsed.

## Changes

- The release watchdog now inspects the current history state.
- If the current base generation exactly matches the pending release, the transaction is settled as a watchdog recovery without showing the workspace exit confirmation.
- If the current state is still the exact sentinel, the controller records a hard stall and deliberately does not issue a second Back request, avoiding traversal past the exit guard.
- If history moved to an unrelated state, the active release is abandoned through the existing generation-mismatch path and a required overlay sentinel is re-established when safe.
- Pending delayed generations are capped at eight entries in addition to the existing 30-second TTL.
- Diagnostics add watchdog-recovered, hard-stall, and pending-trim counters. They contain no URL, file, audio, report text, credentials, or user identity.
