# v1.5.91 Cancellable Audio Pipeline and Performance Guards

## Audit findings

The full v1.5.90 baseline passed 311 static and behavioral checks, but the runtime audit found cancellation and performance gaps outside those contracts. Mastering decode and pitch/BPM work continued until completion after a batch or track cancellation. Analysis and pitch workers also used separate lifecycle code, and a Worker failure could move a large track onto a blocking main-thread implementation.

## Changes

- A mastering task owner now carries the AbortSignal through decode, emergency analysis, and pitch/BPM conversion.
- Master-preview pitch/BPM conversion uses the preview job signal and job identity.
- Analysis and pitch/BPM workers run through `FoxBearWorkerJobService`.
- Both workers echo `__foxbearJobId` and publish staged progress records.
- Cancellation and timeout terminate the Worker and remove its active diagnostics entry.
- Worker-declared `{ok:false}` results reject through the shared service and are retained as failed diagnostics with their error code.
- Pitch progress updates are accepted only while the same mastering job still owns the track.
- Large analysis and pitch jobs reject rather than freezing the UI with synchronous fallback.
- Small files retain compatibility fallback.
- Preview slicing copies from a `Float32Array.subarray()` directly into the destination channel.
