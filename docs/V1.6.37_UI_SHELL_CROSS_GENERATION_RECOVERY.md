# v1.6.37 UI Shell Cross-Generation Recovery

## Incident

A newly activated service worker could claim an already-open previous-generation page, purge its cache, and then reject that page's exact CSS/JavaScript requests as stale. The HTML still existed, but the application UI could appear missing or fail to boot.

## Fix

- Retain the two most recent legacy shell caches during normal activation.
- Serve stale-generation script/style/worker requests only from an exact retained cache-key match, preserving SRI integrity.
- Continue rejecting any stale request that has no exact cached bytes rather than mixing current bytes with old integrity metadata.
- Add a boot-level UI shell recovery service and minimal fallback stylesheet.
- Remove accidental hidden/inert/zero-opacity shell state and expose a readable safety UI when core styles fail.
- Record only bounded resource path suffixes and recovery counters; no user files or content are collected.
