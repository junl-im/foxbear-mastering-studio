# v1.6.50 Kakao Centered Entry Notice

## Problem

KakaoTalk's in-app browser can run the mastering studio, but client-generated mastered Blob downloads may be delayed, blocked, or silently ignored by the WebView. Existing guidance was available only after users reached download recovery controls, so first-time users could complete a long master before learning about the browser limitation.

## Patch

- Detect KakaoTalk entry before the main application boot.
- Show a large centered compatibility notice without preventing the studio from loading underneath it.
- Explain that mastered-file downloads may not work reliably in KakaoTalk.
- Direct users to the upper-right Kakao menu and **Open in another browser** for Chrome, Safari, or the device default browser.
- Explain that installing FoxBear to the home screen as a PWA provides an app-like, more stable workflow.
- Dismiss on the first screen touch or Escape key with a smooth fade/slide transition.
- Auto-dismiss after eight seconds and show a matching countdown bar.
- Suppress the notice in normal browsers, installed standalone PWA mode, and the explicit external-browser redirect flow.

## Interaction safety

The full-screen visual layer uses `pointer-events: none`, while the notice card itself remains touch-aware. A capture-phase screen listener dismisses the notice without permanently blocking the studio. Global listeners and timers are removed on dismissal, and the DOM node is removed after the exit transition.
