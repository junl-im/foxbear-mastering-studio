# v1.5.55 Automatic Incident Mail Reporting and Full Risk Audit

## Scope

This audit covers the browser boot graph, service worker, Firebase bridge and rules, mastering recovery, export paths, release metadata, package scripts, documentation, and the new server-side email delivery path.

## Implemented architecture

1. Critical browser failures are normalized by `src/boot/incident-reporter.js`.
2. Sensitive text is reduced before transmission. Audio, filenames, PCM buffers, and complete local paths are not included.
3. Failed submissions are held in a bounded localStorage queue and retried after connectivity/Firebase recovery.
4. Anonymous Firebase Auth writes a strict create-only `incidentReports` document.
5. A Firestore `onDocumentCreated` Cloud Function loads the Gmail app password from Secret Manager and sends an email to `mcwoogi@gmail.com`.
6. The Function writes `delivery.status` back to the report. The submitting anonymous user may read only that report's delivery status.

## Protection controls

- Client duplicate cooldown: 15 minutes.
- Client automatic limits: 5 per session and 12 per UTC day.
- Server duplicate cooldown: 30 minutes per fingerprint.
- Server email limit: 40 messages per UTC day.
- Function retry disabled to reduce duplicate SMTP delivery after an ambiguous send result.
- HTML escaping and text length limits before mail generation.
- Gmail credential never appears in browser code, repository configuration, `.env.example`, or ZIP artifacts.
- Reports and server state carry `expiresAt`; Firebase TTL must be enabled manually.
- User-visible opt-out and a test-email workflow are included in Program Information.

## Fixed defects

### Critical release-generation split

The working tree identified itself as v1.5.54 while `index.html` loaded v1.5.53 assets. That could combine stale HTML, a newer service worker, and incompatible runtime modules. v1.5.55 re-synchronizes package, HTML, build info, manifest, service-worker cache, worker URLs, SRI, and handoff metadata.

### Invalid HTML boot placement

`mastering-quality-audit-service.js` was placed after `</body>`. It is now part of the ordered deferred boot graph before `app.js`.

### No operational visibility

Previously a remote user could experience a boot, mastering, or export failure without producing any durable report. Critical paths now submit privacy-reduced diagnostics.

### Duplicate document retry loop

Deterministic report IDs could make a repeated Firestore create fail and remain in the local retry queue. The client now checks for an existing owner-readable report and treats it as deduplicated success.

### Offline queue loss ordering

The queue flush previously reconstructed remaining entries with fragile index arithmetic. It now retains the failed item and every later item directly.

## Remaining risks

### High

- **Not active until deployed:** Source code alone cannot send mail. `FOXBEAR_GMAIL_APP_PASSWORD`, Firestore rules, and `sendIncidentEmail` must be deployed and tested.
- **App Check not enforced:** Anonymous Auth plus strict rules and rate limits reduce abuse but do not prove requests came from the genuine site. Add and enforce Firebase App Check before public expansion.
- **SMTP is not exactly-once:** A network break after Gmail accepts a message but before the Function records success can create uncertainty. Retries are disabled to prefer a missed retry over duplicate mail.
- **Transient mail failures are durable but not retried automatically:** Failed delivery is recorded in Firestore. A dead-letter/admin retry workflow is still needed.
- **Gmail account restrictions and quotas:** App-password availability and provider limits can block sending. The deployment owner must verify the account configuration.

### Medium

- **Seven moderate npm audit findings:** Current Firebase Admin dependencies pull vulnerable UUID-related code through Cloud Storage packages. No high or critical finding was reported, and the affected Storage path is unused by this Function, but the dependency chain should be updated when upstream releases resolve it. Do not downgrade Firebase Admin merely to silence the audit.
- **Client reports are untrusted input:** They are useful diagnostics, not authoritative security logs. Server-side validation, escaping, and caps are present.
- **Remote Firebase SDK dependency:** A first-load outage or block of `gstatic.com` can prevent both app Firebase functions and immediate incident submission. The local queue can only retry after the SDK becomes reachable.
- **LocalStorage limitations:** Private mode, quota errors, or storage clearing can remove queued reports. Critical errors are still retained in runtime health for the active page.
- **Large boot surface:** Many independent deferred scripts increase ordering and cache-generation risk. Version/SRI/service-worker checks reduce but do not eliminate it.
- **Large `src/app.js`:** Central orchestration remains difficult to reason about. Continue splitting mastering, reporting, and UI orchestration into services.
- **No production source maps:** Minified or browser-generated stacks may be less actionable. Add release-bound source maps to a private artifact store.

### Low / operational

- Automated reporting intentionally ignores ordinary warnings to avoid mail noise.
- User cancellation and browser download dismissal are not treated as errors.
- Test mail can be server-suppressed if repeated within the fingerprint cooldown.
- Firestore TTL deletion is asynchronous after policy activation.

3. Add a scheduled dead-letter retry with a strict retry count and idempotency key.

## Deployment checklist

```bash
npm --prefix functions install
firebase login
firebase use foxbear-music
firebase functions:secrets:set FOXBEAR_GMAIL_APP_PASSWORD
firebase deploy --only firestore:rules,functions:sendIncidentEmail,hosting
```

Do not paste the Gmail app password into chat, source files, `.firebaserc`, `.env`, GitHub Actions logs, or Firebase Remote Config.

After deployment, open Program Information, keep automatic reporting enabled, press **테스트 메일**, and verify both `delivery.status = emailed` and receipt at `mcwoogi@gmail.com`.
