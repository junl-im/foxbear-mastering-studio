# v1.5.63 Incident Mail Quota and Summary Recovery

## 발견된 예외사항

1. v1.5.62는 KST 업무 기준이 아니라 UTC 날짜 문서로 일일 SMTP 한도를 계산했다. 한국 시간 00:00~09:00 구간에서 한도 초기화 시점이 운영 기대와 달랐다.
2. 신규 신고가 일일 한도에 걸리면 `suppressed-rate-limit`로 종료되어 다음 날에도 자동 재전송되지 않았다.
3. 함수가 SMTP 예약 직후 중단되면 `reservedCount`가 남을 수 있었고, 이후 같은 신고가 중복 억제되거나 다음 날짜로 넘어갈 때 예약 수가 회수되지 않는 경로가 있었다.
4. 일일 요약은 첫 500건만 읽고 추가 신고 존재 여부를 표시하지 않았다.
5. 일일 요약이 09:00 발송에 실패하면 같은 날짜 요약을 다시 시도하는 스케줄이 없었다.
6. SMTP 호출이 오류 없이 끝나더라도 수신 승인 배열이 비어 있는 비정상 결과를 성공으로 기록할 수 있었다.

## v1.5.63 변경

- 발송 한도 상태 문서를 `dailyKst_YYYY-MM-DD`로 분리하고 모든 계산을 Asia/Seoul 날짜로 통일했다.
- 한도 초과 신고를 `failed / daily-email-limit`로 저장하고 다음 KST 자정 5분 후 자동 재시도한다.
- 과거 `suppressed-rate-limit` 문서도 감시 쿼리에서 회수해 마이그레이션한다.
- 신고 문서에 `reservationActive`와 `reservationDayKey`를 기록하고 성공·실패·중복 억제·한도 연기 시 예약 카운터를 정확히 반환한다.
- 요약 집계를 500건 단위로 페이지 처리하며 최대 5,000건 이후 추가 데이터가 있으면 메일에 제한 사실을 표시한다.
- 요약 메일을 09/12/15/18/21시 KST에 재검사하고 최근 3일의 미발송 요약을 보충한다.
- 날짜별 고정 Message-ID와 요약 임대 ID를 적용해 상태 기록 실패 후 재실행의 중복 위험을 낮춘다.
- Gmail 앱 비밀번호를 공백 제거 후 정확히 16자의 영숫자로 검증한다.
- SMTP가 수신자를 한 명도 승인하지 않으면 `FOXBEAR_SMTP_NO_ACCEPTED_RECIPIENT` 실패로 기록한다.

## 배포 확인

- Firestore Rules, Indexes, 네 개 Incident Functions를 함께 배포한다.
- KST 일일 한도 테스트는 테스트 프로젝트에서 한도를 낮춰 다음 날짜 자동 이월을 확인한다.
- 요약 테스트는 500건 초과 fixture 또는 Emulator로 페이지 커서와 고정 Message-ID를 확인한다.
- 실제 Gmail 수신과 Secret 유효성은 배포 권한이 있는 환경에서 확인해야 한다.
